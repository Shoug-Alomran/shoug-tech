Final Exam Cheat Sheet

Chapter 1: Introduction to Software Construction

Construction

  • Coding, verifying, debugging, integrating
  • AI output: plausible, not guaranteed
  • You own every line

Simple code

  • KISS
  • Guard clauses, named constants
  • Small methods, no duplication
  • Names reveal intent
  • Comments: why, not what

Tools

  • Parser → AST
  • Compiler: ahead of time
  • Interpreter: runs directly

Git

  • clone, status, add, commit, push, pull
  • Push fails until you pull
  • main = production-ready

JUnit

  • @Test, @BeforeEach
  • assertEquals / True / False
  • TDD: Red, Green, Refactor
  • Test null, empty, boundary, error

Do not fall for

  • AI makes complexity worse, not better
  • Never commit secrets
  • AI tests can share the AI's mistake

Chapter 2: Generics and Lambda Expressions

Lambdas

  • (params) -> body
  • Target: functional interface (one abstract method)
  • Same parameters and return type
  • Pass to / return from methods

Generics

  • class Box<T>
  • class Pair2<T, S>
  • <T> before return type for methods
  • T... = varargs
  • No primitives: List<Integer>

Subtyping

  • List<Integer> is not a List<Object>
  • List<?> accepts any list
  • ? extends X: X or subclasses

Collections

  • List<String> l = new ArrayList<>()
  • add, get, set, remove, iterator
  • Iterator: hasNext, next, remove

Do not fall for

  • Two abstract methods means no lambda
  • No primitive type arguments

Chapter 3: Dependency Management, Exception Handling and Logging

Maven

  • pom.xml, GAV
  • Plugins → goals
  • validate, compile, test, package, verify, install, deploy
  • install = local, deploy = remote
  • clean and site lifecycles

Exception types

  • Unchecked: RuntimeException, Error
  • Checked: all other Exceptions
  • Checked = catch or declare

Keywords

  • throw: one object, in body
  • throws: signature, declares
  • finally: always runs
  • Specific catch blocks first

Using them

  • try/catch for unexpected only
  • Custom: extends Exception / RuntimeException
  • Don't swallow; close in finally

Assertions

  • assert cond : msg
  • Off by default; -ea
  • Never for public arguments

Logging

  • SEVERE, WARNING, INFO, DEBUG, TRACE
  • SLF4J facade → Logback / Log4j
  • Never log secrets

Do not fall for

  • install vs deploy
  • ClassNotFoundException is checked
  • Order of catch blocks
  • The empty catch block
  • Never check public arguments with assert

Chapter 4: Advanced OO Concepts

Relationships

  • Association: independent
  • Aggregation: has-a, parts survive
  • Composition: parts die with whole
  • Inheritance: is-a

Constructors

  • Not inherited; super(...) first
  • Implicit super() if none
  • Chain: top class prints first
  • No no-arg super → compile error

Override vs overload

  • Override: same signature, run time
  • Overload: different params, compile time
  • private: not overridden; static: hidden
  • Dynamic binding: actual class upward
  • Downcast after instanceof

final / abstract

  • final method: no override
  • final class: no extend (String)
  • abstract method: must override

Interfaces

  • Methods public abstract; fields public static final
  • default, static (8); private (9)
  • Extend one, implement many
  • Weak is-a → interface
  • Composition + interface > deep tree

Objects

  • Private constructor: utility, shared init, factory
  • Immutable: private, no setters, no leaks
  • compareTo: neg / 0 / pos
  • Cloneable = marker; deep-copy mutable fields

Do not fall for

  • Calling the superclass constructor by name
  • private and static methods can't be overridden
  • final ≠ abstract
  • No setters ≠ immutable
  • final fields and clone

Chapter 5: Multithreading and Concurrency

Basics

  • Thread: smallest unit, shares process memory
  • Concurrency: one CPU; parallelism: many
  • Runnable = task; Thread = worker
  • start() → new thread; run() = normal call

Methods

  • States: New, Ready, Running, Blocked, Finished
  • isAlive false only New / Finished
  • Priority 1-10, default 5, a hint
  • sleep, yield, join, interrupt

Pools

  • Executors.newFixedThreadPool(n)
  • newCachedThreadPool()
  • execute, shutdown, isTerminated

Races

  • Read-modify-write interleaving
  • synchronized method: lock on object
  • static synchronized: lock on class
  • synchronized (this) { }

Locks

  • lock(); try { } finally { unlock(); }
  • Fair = longest waiter, no starvation
  • Conditions: await / signal

Deadlock and more

  • Circular wait on locks
  • Fix: resource ordering
  • Collections.synchronizedList
  • Fail-fast → ConcurrentModificationException
  • Fork/Join: RecursiveAction, ForkJoinPool

Do not fall for

  • start() vs run()
  • Priority is only a hint
  • Forgetting unlock
  • Iterators are fail-fast

Chapter 6: REST APIs and Spring Boot

Spring

  • Spring Boot: opinionated, embedded Tomcat
  • IoC: framework calls your code
  • DI: dependencies given, not new
  • Bean: object in IoC container

CRUD

  • POST /v1/products → 201 + Location
  • GET /{id} → 200 (404 if missing)
  • PUT /{id} → 204
  • DELETE /{id} → 204

REST principles

  • Uniform interface, client-server
  • Stateless, cacheable
  • Layered, code on demand
  • Nouns in paths, versioning, pagination

Codes

  • 400 bad input
  • 401 not authenticated
  • 403 not allowed
  • 404 not found, 500 server
  • Idempotent: GET, PUT, DELETE

Annotations

  • @RestController, @RequestMapping
  • @Get/Post/Put/DeleteMapping
  • @PathVariable, @RequestBody, @RequestParam
  • ResponseEntity

Data

  • record = immutable data class
  • extends CrudRepository<Product, Integer>
  • PagingAndSortingRepository, page from 0
  • H2 in-memory; MySQL persistent
  • Soft delete; audit trail

Do not fall for

  • 200 vs 201 vs 204
  • 401 vs 403
  • Credentials in properties files

Chapter 7: Software Security

Identity

  • Authentication: who → 401
  • Authorization: what → 403
  • Session token in cookie
  • RBAC: hasRole("ADMIN")

Browser rules

  • Origin = protocol + domain + port
  • SOP: can't READ other origin
  • CORS: server allows origins
  • @CrossOrigin(origins = ...), never empty

Attacks

  • CSRF: forged request with your cookies
  • → CSRF token, SameSite
  • XSS: attacker script runs on site
  • → escape, CSP, HttpOnly
  • XSS can bypass CSRF tokens

Spring defaults

  • Auth on all requests
  • Unknown URL → 401, not 404
  • CSRF on POST/PUT/DELETE
  • Default user, new password each start
  • Firewall rejects unsafe characters

Headers

  • nosniff: MIME sniffing
  • X-Frame-Options DENY: clickjacking
  • Cache-Control no-store
  • HSTS: HTTPS only
  • CSP: XSS

Config and JWT

  • SecurityFilterChain, UserDetailsService
  • UserPrincipal = adapter; BCrypt
  • JWT = Header.Payload.Signature
  • Signed, not encrypted
  • Bearer header; short expiry

Do not fall for

  • SOP blocks reading, not sending
  • @CrossOrigin with no arguments
  • Why an unknown URL returns 401, not 404
  • Disabling CSRF is only safe without cookies
  • Signed is not encrypted
