CH 01

How the web works

Client-server and HTTP

  • Browser (client) sends an HTTP request; the server returns a response (status, headers, body).
  • URL = protocol://host:port/path?query#fragment.
  • DNS turns the host name into an IP address. HTTP is stateless (cookies and sessions add state).
  • HTTPS = HTTP over TLS (port 443; HTTP 80).

Methods and status codes

  • GET (read), POST (create), PUT/PATCH (update), DELETE.
  • 200 OK · 201 Created · 301 Moved · 304 Not Modified · 400 Bad Request · 401 Unauthorized · 403 Forbidden · 404 Not Found · 500 Server Error.
2xx success, 3xx redirect, 4xx client error, 5xx server error.

Front end vs back end

Front end: HTML (structure), CSS (presentation), JavaScript (behaviour) in the browser. Back end: server code (Node.js), databases, APIs (often JSON over HTTP).

CH 02

HTML

Skeleton

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Page</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>Heading</h1>
  <script src="app.js"></script>
</body>
</html>

Elements

  • Block (div, p, h1–h6, ul/ol/li, section, header, nav, main, footer, article) vs inline (span, a, img, strong, em).
  • Links <a href="url" target="_blank">; images <img src alt> (alt for accessibility).
  • Tables: table, tr, th, td, colspan/rowspan.
  • Semantic elements describe meaning (header, nav, article) and help SEO and accessibility.

Forms

<form action="/register" method="POST">
  <label for="email">Email</label>
  <input type="email" id="email" name="email" required>
  <input type="password" name="pw" minlength="8">
  <select name="major"><option>SE</option></select>
  <input type="radio" name="g" value="f"> <input type="checkbox">
  <textarea name="msg"></textarea>
  <button type="submit">Send</button>
</form>
Without a name attribute, an input's value is not sent with the form.
CH 03

CSS

Selectors and specificity

  • Element p, class .card, id #main, descendant nav a, child ul > li, group h1, h2, pseudo-class a:hover, li:nth-child(2), attribute input[type="email"].
  • Specificity: inline > id > class/attribute/pseudo-class > element. Equal specificity → the later rule wins. !important overrides.
Specificity as (ids, classes, elements): #nav .item a = (1, 1, 1).

Box model

content → padding → border → margin. box-sizing: border-box makes width include padding and border.

Default width = content only: width 200 + padding 20 each side + border 5 each side = 250 px total.

Layout

  • display: block, inline, inline-block, none, flex, grid.
  • Flexbox: display:flex; justify-content (main axis), align-items (cross axis), flex-direction, flex-wrap, gap.
  • Grid: grid-template-columns: repeat(3, 1fr).
  • position: static, relative, absolute (to the nearest positioned ancestor), fixed, sticky.
  • Responsive: @media (max-width: 600px) { ... }, relative units (%, em, rem, vw).
CH 04

JavaScript

Variables and types

  • let (block scope, reassignable), const (block scope, not reassignable), var (function scope, hoisted).
  • Types: number, string, boolean, null, undefined, object, array, function.
  • === strict (no type conversion) vs == loose: "5" == 5 true, "5" === 5 false.
"5" + 3 = "53" but "5" - 3 = 2. typeof null is "object". 0.1 + 0.2 !== 0.3.

Functions

function add(a, b) { return a + b; }
const add2 = (a, b) => a + b;
[1, 2, 3].map(x => x * 2)         // [2, 4, 6]
[1, 2, 3].filter(x => x > 1)      // [2, 3]
[1, 2, 3].reduce((s, x) => s + x, 0) // 6

Objects, arrays, JSON

  • Object {name: "Shoug", age: 21}; access obj.name or obj["name"].
  • Array methods: push, pop, shift, unshift, slice, splice, indexOf, includes, forEach, sort.
  • JSON.stringify(obj) → string; JSON.parse(str) → object.
  • Template literals: ` Hi ${name} `.

Async

  • Callbacks → Promises → async/await.
  • fetch(url).then(r => r.json()).then(data => ...)
  • setTimeout(fn, 0) runs after the current code (event loop).
CH 05

JavaScript in the browser (DOM)

Selecting and changing

const btn = document.querySelector("#save");
const items = document.querySelectorAll(".item");
document.getElementById("title").textContent = "Hi";
el.innerHTML = "<b>bold</b>";      // parses HTML
el.style.color = "red";
el.classList.add("active"); el.classList.toggle("open");
const li = document.createElement("li");
list.appendChild(li); li.remove();

Events

btn.addEventListener("click", (e) => { ... });
form.addEventListener("submit", (e) => {
  e.preventDefault();             // stop the page reload
  const v = form.elements.email.value;
});

Events bubble up from the target to its ancestors (event delegation uses this). Common events: click, submit, input, change, keydown, load, DOMContentLoaded.

A script in <head> runs before the elements exist: use defer or put the script at the end of body.

Storage and validation

localStorage.setItem("k", v) (persists), sessionStorage (per tab), cookies (sent to the server). Validate on the client for UX and always again on the server for security.

CH 6–7

Node.js, Express and databases

Node.js

JavaScript on the server (V8), single-threaded, event-driven, non-blocking I/O. Modules: require/module.exports (CommonJS) or import/export. npm installs packages listed in package.json.

Express

const express = require("express");
const app = express();
app.use(express.json());                  // parse JSON bodies
app.use(express.static("public"));
app.get("/users/:id", (req, res) => {
  res.json({ id: req.params.id, q: req.query.sort });
});
app.post("/users", (req, res) => {
  const user = req.body; res.status(201).json(user);
});
app.listen(3000);
  • req.params (route), req.query (?a=1), req.body (POST data). Middleware runs in order and calls next().
  • REST: resources as URLs, HTTP methods as actions.

Databases

  • SQL (MySQL, PostgreSQL): tables, schema, SQL queries, joins. NoSQL (MongoDB): JSON documents, flexible schema.
  • CRUD: create, read, update, delete ↔ POST, GET, PUT/PATCH, DELETE.
  • Use parameterized queries to prevent SQL injection; hash passwords (bcrypt); keep secrets in environment variables.
