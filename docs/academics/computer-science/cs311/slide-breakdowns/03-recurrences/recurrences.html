Read this first

The big picture

In one sentenceA recursive algorithm's running time is an equation that refers to itself, and three methods turn that equation into a normal Big-O.

Loops can be read straight off the page, but recursion can't. A recurrence is how you write down what recursion costs. Every divide-and-conquer algorithm from here on needs this, and the Master theorem is one of the most dependable sets of marks in the course.

Where this fits

This uses Lecture 2's counting. Lecture 4's merge sort and quick sort are direct applications, and dynamic programming returns to the same recurrences.

By the end you can

  • Write the recurrence for a recursive algorithm
  • Solve recurrences with the iteration method
  • Apply the Master theorem and pick the correct case
  • Use the extended Master theorem with log factors
  • Prove a guess using substitution

Lesson 1

Writing the recurrence

Must knowSlides 2-15

A recurrence describes a function in terms of its value on smaller inputs. To write one, answer just two questions.

Step by step

Turn code into a recurrence

  1. How many recursive calls, and on what size? That gives the T(...) terms.
  2. How much work outside the recursive calls? That gives the extra term.
  3. What's the base case? Usually T(1) or T(0) is a constant.
Worked example

Binary search (slide 7)

mid is computed, x is compared (constant work, c), and then one call is made on half of the array.

T(n) = T(n/2) + c

Worked example

Factorial (slide 12)

One call on n − 1, plus a multiplication: constant work.

T(n) = T(n − 1) + 1

Slide 15's table is worth committing to memory.

Recurrence What the algorithm does Solution
T(n) = T(n/2) + 1 Halves, constant work O(log n)
T(n) = T(n/2) + n Halves, scans everything O(n)
T(n) = 2T(n/2) + 1 Two halves, constant work O(n)
T(n) = 2T(n/2) + n Two halves, scans everything O(n log n)
T(n) = T(n−1) + 1 Removes one, constant work O(n)
T(n) = T(n−1) + n Removes one, scans everything O(n²)
T(n) = 2T(n−1) + 1 Two calls, each one smaller O(2ⁿ)
What the slide really means

Slide 8's handwriting | T(n) = T(n) would never end

The size must shrink. A recursive call on the same size never terminates, so usually you'll see subtraction or division on the input. That's the slide's point: subtraction gives you the iteration method's easy patterns, and division is the Master theorem's territory.

Remember
  • A recurrence defines a function in terms of smaller inputs
  • Count recursive calls for the T terms and non-recursive work for the extra term
  • Binary search: T(n) = T(n/2) + c
  • Merge-style: T(n) = 2T(n/2) + n is O(n log n)
  • T(n) = 2T(n−1) + 1 is exponential
Lesson 2

Method 1: Iteration

Must knowSlides 16-19

Keep expanding the formula until you see a pattern, then jump to the base case.

Step by step

Solve T(n) = c + T(n/2)

  1. Expand once: T(n) = c + c + T(n/4).
  2. Twice: T(n) = c + c + c + T(n/8).
  3. Pattern after k steps: T(n) = k·c + T(n / 2k).
  4. Stop when n / 2k = 1, meaning k = lg n.
  5. So T(n) = c·lg n + T(1) = Θ(lg n).
Step by step

Solve T(n) = n + 2T(n/2)

  1. Expand: n + 2(n/2 + 2T(n/4)) = n + n + 4T(n/4).
  2. Again: n + n + n + 8T(n/8).
  3. After i steps: i·n + 2iT(n / 2i).
  4. Stop at i = lg n: n lg n + n·T(1).
  5. So T(n) = Θ(n lg n).

The recursion tree shows why.

Worked example

Subtraction forms, from the handwriting on slide 11

  • T(n) = T(n−1) + n: sum n + (n−1) + ... + 1 = O(n²).
  • T(n) = T(n−1) + log n: sum of logs = log(n!) = O(n log n).
  • T(n) = 2T(n−1) + 1: expands to 1 + 2 + 4 + ... + 2n−1 = O(2ⁿ).
Remember
  • Iteration expands the recurrence until a pattern appears
  • Stop when the argument reaches the base case
  • T(n) = c + T(n/2) is Θ(lg n)
  • T(n) = n + 2T(n/2) is Θ(n lg n)
Lesson 3

Method 2: The Master theorem

Must knowSlides 20-29

It's a cookbook for one form:

Master form
T(n) = a·T(n/b) + f(n), where a ≥ 1, b > 1, f(n) > 0
Symbol Meaning
a Number of subproblems
b How much each shrinks
f(n) Work outside the recursion

The idea: compare f(n) with nlogba. Whichever is bigger wins. On a tie, you get an extra log.

Case Condition Answer
1 f(n) is smaller: O(nlogba − ε) Θ(nlogba)
2 They tie: Θ(nlogba) Θ(nlogba lg n)
3 f(n) is bigger: Ω(nlogba + ε), and a·f(n/b) ≤ c·f(n) for some c < 1 Θ(f(n))
Think of it like this

A tug-of-war

On one side, the leaves: lots of tiny subproblems (nlogba). On the other, the root: the work f(n). The stronger side sets the running time. If they are evenly matched, every level contributes equally, so you multiply by the number of levels, lg n.

Step by step

The procedure (slide 22)

  1. Check the recurrence fits the form.
  2. Extract a, b and f(n).
  3. Compute nlogba.
  4. Compare with f(n) and pick the case. For Case 3, also check regularity.

Every example from the slides, worked out:

Recurrence a, b nlogba f(n) Case Answer
2T(n/2) + √n 2, 2 n √n, smaller 1 Θ(n)
9T(n/3) + n 9, 3 n² n, smaller 1 Θ(n²)
2T(n/2) + n 2, 2 n n, tie 2 Θ(n lg n)
T(2n/3) + 1 1, 3/2 n⁰ = 1 1, tie 2 Θ(lg n)
2T(n/2) + n² 2, 2 n n², bigger 3 Θ(n²)
3T(n/4) + n lg n 3, 4 n0.79 n lg n, bigger 3 Θ(n lg n)
Worked example

The regularity check for 2T(n/2) + n²

Need a·f(n/b) ≤ c·f(n). Here: 2 × (n/2)² = n²/2 ≤ c·n². So c = 1/2, which is less than 1. It passes.

Exam trap

Master doesn't fit everything

T(n) = T(n − 1) + n has subtraction, so no Master theorem: use iteration. And Case 3 demands the regularity check; don't skip it.

Try itSolve T(n) = 4T(n/2) + n.

a = 4, b = 2, nlog₂4 = n². f(n) = n is smaller. Case 1: Θ(n²).

Try itSolve T(n) = 4T(n/2) + n².

nlog₂4 = n², which ties with f(n). Case 2: Θ(n² lg n).

The extended version (slide 23)

If f(n) = Θ(nk logp n), compare a with bk.

Comparison Sub-case Answer
a > bk Θ(nlogba)
a = bk p > −1 Θ(nlogba logp+1 n)
a = bk p = −1 Θ(nlogba log log n)
a = bk p < −1 Θ(nlogba)
a < bk p ≥ 0 Θ(nk logp n)
a < bk p < 0 O(nk)
Worked example

2T(n/2) + n log n

a = 2, b = 2, k = 1, p = 1. a = bk and p > −1, so Θ(n log² n). The basic Master theorem can't handle this, since n log n isn't polynomially larger than n.

Remember
  • Form: T(n) = aT(n/b) + f(n), with a ≥ 1 and b > 1
  • Compare f(n) with n to the (log base b of a)
  • Case 1: leaves win. Case 2: tie, multiply by lg n. Case 3: root wins, check regularity
  • Recurrences that subtract do not fit the Master theorem
  • Extended form compares a with b^k and uses the log exponent p
Lesson 4

Method 3: Substitution

Must knowSlides 30-35

Guess the answer, then prove it with induction. It's more work, but works on anything if you can guess.

Step by step

Prove T(n) = 2T(n−1) + 1 with T(0) = 0 solves to 2ⁿ − 1

  1. Base case: T(0) = 2⁰ − 1 = 0. True.
  2. Hypothesis: assume T(n−1) = 2n−1 − 1.
  3. Inductive step: T(n) = 2(2n−1 − 1) + 1 = 2ⁿ − 2 + 1 = 2ⁿ − 1. Done.
Step by step

Prove T(n+1) = 3T(n) + 4 with T(1) = 1 solves to 3ⁿ − 2

  1. Base case: T(1) = 3 − 2 = 1. True.
  2. Hypothesis: T(n) = 3ⁿ − 2.
  3. Step: T(n+1) = 3(3ⁿ − 2) + 4 = 3n+1 − 6 + 4 = 3n+1 − 2. Done.
Step by step

Prove T(n) = 2T(n/2) + n is O(n lg n)

  1. Goal: T(n) ≤ c·n lg n.
  2. Hypothesis: T(n/2) ≤ c(n/2)lg(n/2).
  3. Substitute: T(n) ≤ 2c(n/2)lg(n/2) + n = cn lg(n/2) + n = cn lg n − cn + n.
  4. Solve for c: this is ≤ cn lg n whenever −cn + n ≤ 0, i.e. c ≥ 1.
Exam trap

Keep the exact form

When you assume T(k) ≤ d·g(k), you must prove the same inequality with the same d. Ending at "d·g(n) + n" and calling it O(g(n)) isn't a proof.

Remember
  • Substitution: guess a solution, then prove it by induction
  • Assume the bound for smaller inputs and prove the same bound for n
  • Find values of the constants that make the proof work
  • T(n) = 2T(n−1) + 1 with T(0) = 0 is 2ⁿ − 1

Quick reference

Standard answers

  • T(n/2)+1: log n
  • T(n/2)+n: n
  • 2T(n/2)+1: n
  • 2T(n/2)+n: n log n
  • T(n−1)+1: n
  • T(n−1)+n: n²
  • 2T(n−1)+1: 2ⁿ

Master theorem

  • T(n) = aT(n/b) + f(n)
  • Compare f(n) with n^(log_b a)
  • f smaller: Θ(n^(log_b a))
  • Tie: Θ(n^(log_b a) lg n)
  • f larger + regularity: Θ(f(n))

Extended master

  • f = n^k log^p n; compare a, b^k
  • a > b^k: Θ(n^(log_b a))
  • a = b^k, p > −1: multiply by log^(p+1)
  • a = b^k, p = −1: multiply by log log n
  • a < b^k, p ≥ 0: Θ(n^k log^p n)

Methods

  • Iteration: expand and spot the pattern
  • Master: only for T(n/b) form
  • Substitution: guess then induct

Base-case trick

  • n/2^k = 1 gives k = lg n
  • n − k = 0 gives k = n
