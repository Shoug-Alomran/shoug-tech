ER-to-Relational Mapping and DDL

The 7-step ER-to-relational mapping algorithm (strong and weak entities, 1:1, 1:N and M:N relationships, multivalued attributes, n-ary relationships), basic DDL (CREATE TABLE, keys, foreign keys, data types, constraints), and step 8 options for mapping specialization.

Notes

  1. 1

    Step 2 weak entity: relation with its attributes + the owner’s primary key as a foreign key; PK = owner PK + partial key.

Exam angle

mapping a weak entity (Blog_Posting)

PredictionQ1

The primary key of a relation mapped from a weak entity is:

  1. A new surrogate key only
  2. The owner’s PK alone
  3. Owner’s PK + the partial key
  4. The partial key alone
Show answer

C. Owner’s PK + the partial key

ER-TO-RELATIONAL MAPPING ALGORITHM (CONTD.)

Notes

  1. 1

    1:N: put the PK of the "1" side as an FK in the "N" side (plus any relationship attributes).

  2. 2

    Memory trick 1:N → the FK goes on the MANY side.

Exam angle

PredictionQ1

EMPLOYEE (N) works for DEPARTMENT (1). Map it by:

  1. Merging both relations
  2. Adding Ssn as a foreign key in DEPARTMENT
  3. Creating a new relation always
  4. Adding Dno as a foreign key in EMPLOYEE
Show answer

D. Adding Dno as a foreign key in EMPLOYEE

    Step 8 specialization options: 8A superclass + subclass relations (any case); 8B subclass relations only (total, disjoint); 8C one relation + type attribute (disjoint); 8D one relation + Boolean flags (overlapping).

Mapping option that uses ONE relation with a Boolean flag per subclass suits:

  3. Overlapping subclasses
