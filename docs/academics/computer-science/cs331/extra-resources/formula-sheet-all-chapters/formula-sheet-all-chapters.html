CHAPTER 01

Introduction: networks, topologies and layers

Breakdown: networks Breakdown: layering

Chapter 1 has only a few formulas, all about counting links and ports in each physical topology. N is the number of devices (nodes) every time.

Topology counts

1.1

Mesh topology

Links = N(N − 1)2
Ports (NICs) per device = N − 1
Cables = Links

Every node has a dedicated point-to-point link to every other node. That is why it costs so much: it needs a lot of wiring and N − 1 I/O ports on each device.

Example
N = 6 devices Links = 6 × 5 / 2 = 15 Ports = 6 − 1 = 5 per device (30 in total) Cables = 15
Watch out Total ports = N(N − 1), which is twice the number of links, because each link uses one port at each end.
1.2

Star, bus and ring

TopologyNumber of linksNotes
StarNOne dedicated link from each node to the central hub/switch. If the hub fails, the whole network fails.
Bus1 main + N drop linesOne backbone cable; each node taps in with a drop line. Less cabling than mesh or star.
RingNEach node is linked to the two nodes on either side of it.
MeshN(N − 1)/2Most secure and robust, most expensive.

Layering

1.3

Protocol data unit (PDU)

PDU of layer n = data from layer n + 1 + header of layer n

Encapsulation: layer N − 1 carries the whole PDU of layer N in its data part without looking inside it. Layer n − 1 provides a service to layer n through the interface between them.

Remember Going down the stack adds headers (the data link layer also adds a trailer); going up removes them.
1.4

Data rate

Data rate = transmission rate = bandwidth

The number of bits sent per second. Defined by the physical layer, along with bit synchronisation between the sender and receiver clocks.

Unit: bits per second (bps)

Signals

2.1

Frequency and period

f = 1T and T = 1f
f
frequency in Hz: cycles per second
T
period in seconds: time for one cycle

Frequency and period are the inverse of each other.

Slide examples
Home power is 60 Hz: T = 1/60 = 0.0166 s = 16.6 ms Period is 100 ms, find f in kHz: 100 ms = 100 × 10⁻³ s = 0.1 s f = 1/0.1 = 10 Hz = 10 × 10⁻³ kHz = 10⁻² kHz
2.2

Bit rate and bit interval

Bit interval = 1Bit rate and Bit rate = 1Bit interval
Bit rate
bits sent per second (bps). Also called digital bandwidth, transmission speed or link capacity.
Bit interval
time needed to send one bit (the digital signal's "period")
Slide example
Bit rate = 2000 bps Bit interval = 1/2000 = 0.0005 s = 0.0005 × 10⁶ μs = 500 μs
2.3

Wavelength

λ = Propagation speed × T
λ = Propagation speedf
λ
wavelength: the distance one cycle occupies (how far a simple signal travels in one period)
f
frequency

The second form comes from substituting T = 1/f. Wavelength depends on both the frequency and the medium.

Unit: metres

Performance: delay

2.4

Propagation time

Propagation time = DistancePropagation speed

How long one bit takes to travel from one node to the other.

  • Distance in metres (m)
  • Speed in m/s
  • Answer in seconds

The propagation speed depends on the medium. Light travels at about 3 × 108 m/s in a vacuum, slower in air, and at about 2/3 of that (≈ 2 × 108 m/s) in a cable.

Watch out Distances are usually given in km. Multiply by 1000 first: 12,000 km = 1.2 × 107 m.
2.5

Transmission time

Transmission time = Message size in bitsBandwidth (bit rate)

How long it takes to push the entire message onto the link.

Remember Propagation → distance / speed.
Transmission → message size / bit rate.
When a question asks when the last bit arrives, add the two.
Watch out Message sizes are often given in bytes (kbyte, Mbyte). Multiply by 8 to get bits before dividing.
2.6

Bandwidth–delay product

Bandwidth–delay product = Bandwidth × Propagation delay

The number of bits that can fill the link at one time: the length of the link measured in bits.

Unit: bits
Think of a pipe Bandwidth is how wide the pipe is, delay is how long it is, and the bandwidth–delay product is how much the pipe holds.
Slide figures
Case 1: 1 bps × 5 s delay = 5 bits on the link Case 2: 5 bps × 5 s delay = 25 bits on the link

Worked slide examples

2.7

Short message: propagation dominates

2.5-kbyte e-mail, bandwidth 1 Gbps, distance 12,000 km, light travels at 2.4 × 108 m/s.

Working
Propagation = (12,000 × 1000) / (2.4 × 10⁸) = 0.05 s = 50 ms Transmission = (2500 × 8) / 10⁹ = 0.000020 s = 0.020 ms

The message is short and the bandwidth is high, so propagation time dominates and transmission time can be ignored.

2.8

Long message: transmission dominates

5-Mbyte image, bandwidth 1 Mbps, distance 12,000 km, light travels at 2.4 × 108 m/s.

Working
Propagation = (12,000 × 1000) / (2.4 × 10⁸) = 0.05 s = 50 ms Transmission = (5,000,000 × 8) / 10⁶ = 40 s

The message is very long and the bandwidth is not very high, so transmission time dominates and propagation time can be ignored.

CHAPTER 03

Data-link layer: control and media access

Breakdown: DLC Breakdown: MAC

Part 1 is framing and error detection (burst errors, parity, CRC, checksum). Part 2 is media access: who gets to send on a shared link, and how much throughput each node gets.

Errors

3.1

Bits hit by a burst error

Bits affected = Data rate × Burst duration

Burst length is counted from the first corrupted bit to the last corrupted bit, so the bits in between need not all be wrong. Higher data rates mean longer bursts.

Slide example: 2 ms burst
1 Kbps: 1 × 10³ × 2 × 10⁻³ = 2 bits 1 Gbps: 1 × 10⁹ × 2 × 10⁻³ = 2,000,000 bits
3.2

Codewords C(n, k)

n = k + r
k
bits in the dataword
r
redundant (check) bits added
n
bits in the codeword actually sent

Simple parity check is C(5, 4): 4 data bits + 1 parity bit.

3.3

Simple parity check

Even parity: total number of 1s (data + parity) is even
  • Detects every single-bit error.
  • Detects a burst only if an odd number of bits changed.
Slide example: "world", even parity
Sent: 11101110 11011110 11100100 11011000 11001001 Received: 11111110 11011110 11101100 11011000 11001001 1s count: 7 6 5 4 4 → 7 and 5 are odd → reject, ask to resend
3.4

Two-dimensional parity

Data goes into a table. The last column holds a parity bit for each row and the last row a parity bit for each column.

  • Detects 1, 2 or 3 errors, but not all 4-bit errors.
  • Can correct a single-bit error: the bad row and bad column cross at it.
3.5

CRC: generator polynomial

x3 + x + 1 → 1011 x2 + 1 → 101

Each power of x that is present becomes a 1, and each missing power a 0, starting from the highest power.

r
degree of the generator = number of divisor bits − 1 = CRC length
Steps
  • Sender: append r zeros to the data, divide with modulo-2 (XOR) division, and replace the zeros with the r-bit remainder.
  • Receiver: divide the whole codeword by the same generator. A remainder of 0 means accept; anything else means the frame is corrupted.
3.6

CRC burst-error detection

Burst lengthMissed (slips by)
≤ rNever: all detected
= r + 1(1/2)r − 1
≥ r + 2(1/2)r
Slide example
x⁶ + 1 (r = 6): all bursts ≤ 6 caught length 7: 1/2⁵ ≈ 0.03 → 3 in 100 missed length ≥8: 1/2⁶ ≈ 0.016 → 16 in 1000 missed x¹⁸ + x⁷ + x + 1 (r = 18): 8 in a million (length 19), 4 in a million (≥ 20) x³² + x²³ + x⁷ + 1 (r = 32): 5 in 10 billion (length 33), 3 in 10 billion (≥ 34)
3.7

Checksum (one's complement)

Checksum = complement of (one's-complement sum of all words)
  • Sender: split into words (16-bit in the Internet), set the checksum to 0, add the words with one's complement addition (a carry out wraps back into the sum), then complement the sum.
  • Receiver: add every word including the checksum, then complement. 0 means accept; anything else means reject.
Slide example (8-bit words)
10101001 + 00111001 = 11100010 → checksum = 00011101 Sent: 10101001 00111001 00011101 Receiver: sum = 11111111 → complement 00000000 → OK
3.8

Forward error correction with XOR

R = C1 ⊕ C2 ⊕ … ⊕ Cn
Lost Ci = R ⊕ (all the other codewords)

Send the codewords with the extra block R. Any one corrupted block can be rebuilt without a retransmission. Chunk interleaving works on the same idea: multimedia can afford to lose one chunk from each packet.

Framing

3.9

Bit stuffing

Flag = 01111110

The sender stuffs one extra 0 after every five consecutive 1s in the data, so the data can never look like the flag. When the receiver sees five 1s, it checks the next bit: a 0 is removed (unstuffed), and a 1 means the flag has arrived.

Example
Data: 01111110 Stuffed: 011111010 (the bold 0 is stuffed)
3.10

Byte stuffing

Byte-oriented framing: put an ESC byte before any flag byte or ESC byte that appears in the data. The receiver removes each ESC and treats the next byte as plain data.

Media access control

3.11

Throughput per node

Controlled access (reservation, polling, token)R/M, fair and no collisions

R
channel rate in bps

number of nodes (stations)
3.12

CSMA timing

Vulnerable time (CSMA) = Tprop, max
p-persistent slot = Tprop, max

Tprop, max is the time a bit takes to travel between the two stations that are furthest apart. The longer it is, the worse CSMA performs.

Persistence methods
  • Non-persistent: idle → send; busy → wait a random time, then sense again.
  • 1-persistent: idle → send; busy → keep listening, then send with probability 1 (collisions guaranteed if two are waiting).
  • p-persistent: idle → send with probability p, or wait one slot with probability 1 − p.
3.13

CSMA/CD numbers

Jam signal = 48 bits

On a collision, stop sending, transmit the 48-bit jam signal, back off for a random time, then rerun the persistence method. CSMA/CD is used by Ethernet (IEEE 802.3) on a bus or a star built around a hub.

3.14

Reservation

Reservation frame = N minislots

One minislot per station. Stations that reserved a slot then send their frames at the full rate R, in order, after the reservation frame.

4.2

Minimum and maximum frame length

Min = 6 + 6 + 2 + 46 + 4 = 64 bytes = 512 bits
Max = 6 + 6 + 2 + 1500 + 4 = 1518 bytes = 12,144 bits
Pad = 46 − data bytes (only when data < 46)
Example
Data = 30 bytes → pad = 46 − 30 = 16 bytes Frame = 6 + 6 + 2 + 46 + 4 = 64 bytes
Watch out The 64 and 1518 limits exclude the 8-byte preamble and SFD. Header + trailer overhead = 6 + 6 + 2 + 4 = 18 bytes.
4.3

Type or length?

value ≥ 0x0600 (1536) → Type (DIX)
value ≤ 0x05DC (1500) → Length (802.3)

Type codes: IP 0800, ARP 0806, Novell IPX 8137, AppleTalk 809B.

Addresses and speed

4.4

MAC address

6 bytes = 48 bits = 3-byte vendor ID + 24-bit serial

Flat (not hierarchical) and burned into the NIC's ROM. Vendor prefixes on the slides: Cisco 00-00-0C, Juniper 00-05-85.

4.5

Unicast, multicast or broadcast

2nd hex digit from the left: even → unicast, odd → multicast

That digit holds the least significant bit of the first byte. All F's (all 1s) is broadcast, a special case of multicast.

Slide example
4A:30:10:21:10:1A → A = 1010 (even) → unicast 47:20:1B:2E:08:EE → 7 = 0111 (odd) → multicast FF:FF:FF:FF:FF:FF → all F's → broadcast
4.6

Full duplex doubles throughput

Full-duplex throughput = 2 × link rate
Slide examples
100 Mbps Ethernet → 200 Mbps 1 Gbps Ethernet → 2 Gbps

Full duplex needs full-duplex NICs, two wire pairs, a switch (not a hub) and point-to-point links. Each station is then its own collision domain, so CSMA/CD is not needed.

6.5

Switch forwarding decision

  • Learn: if the source MAC address is not in the table, add it with its incoming port. If it is already there, update the port and the time.
  • Destination found, different port: forward out of that port.
  • Destination found, same port: drop the frame.
  • Destination not found: flood out of every port except the one it came in on.
  • Broadcast or multicast: send out of all ports.
Watch out A loop plus flooding causes a broadcast storm. The spanning tree protocol blocks ports to remove the loops.

CHAPTER 07

Network layer: IPv4 addressing and subnetting

Breakdown: data transfer

This is the biggest calculation chapter after chapter 2. Almost every subnetting question uses the same three facts: the mask length n, the host bits 32 − n, and an AND with the mask.

Address space

7.1

IPv4 address space

232 = 4,294,967,296 addresses

32 bits = 4 octets. Each octet is 0–255 in dotted-decimal notation.

Slide examples
10000001 00001011 00001011 11101111 → 129.11.11.239 111.56.45.78 → 01101111 00111000 00101101 01001110 75.45.301.14 → error: 301 > 255
7.2

Addresses in a block

Addresses = 232 − n
Usable hosts = 232 − n − 2
n
mask (prefix) length: the /n

Subtract 2 because the first address (host bits all 0) is the network address and the last (host bits all 1) is the broadcast address.

7.3

The four addresses of a block

Last hostall 1s, then a 0192.168.10.254
Directed broadcastall 1s192.168.10.255
Broadcast = Network + 232 − n − 1

Limited broadcast is 255.255.255.255. Routers never forward it. A directed broadcast (network ID + host bits all 1s) is forwarded to the target network.

Masks and subnetting

7.6

7.8

Subnets and hosts from a mask

Subnets = 2(subnet mask length − classful mask length)
Hosts per subnet = 2(32 − subnet mask length) − 2

A valid subnet mask is longer than the class's default mask and no longer than /30.

Example

7.9

Subnetting steps (from the slides)

Bits borrowed = number of binary digits in (subnets needed − 1)
New mask = default mask + bits borrowed
  1. Subtract 1 from the number of subnets needed.
  2. Convert the result to binary and count its bits.
  3. Add that count to the default mask.
  4. The weight is 2 raised to the position of the last 1-bit in the mask, counted from the right of its octet. This equals 256 − the mask octet.
  5. The first subnet is the original network address. Keep adding the weight to that octet, and stop when the result would pass 255.
Slide example: 192.168.1.0/24, 5 subnets needed
5 − 1 = 4 = 100₂ → 3 bits → /24 + 3 = /27 Weight = 256 − 224 = 32 → 8 subnets (5 used, 3 spare) 192.168.1.0/27, .32/27, .64/27, .96/27, .128/27, …

IPv4 datagram

7.10

Header and length numbers

Header ≥ 20 bytes (no options)
Total length = header + data ≤ 65,535 bytes

So data = total length − header length. The header checksum covers the header only and is recomputed at every router, because fields such as the TTL change.

7.11

Time to live

TTL ← TTL − 1 at every router; drop at 0

Stops lost packets from looping between routers forever.

7.12

Fragmentation flags

FlagMeaning
M = 1More fragments follow (not the last)
M = 0Last fragment
D = 1Do not fragment. If the packet is bigger than the link's MTU, it is dropped.

Fragmentation happens at the source or at any router; reassembly happens only at the destination. The packet must fit the next link's MTU.

CHAPTER 08

Network layer: routing of packets

Breakdown: routing

Routing reduces to two calculations: the least-cost path through a weighted graph, and matching a destination address against a forwarding table.

Shortest path

8.1

Path cost

Cost(path) = Σ cost of each link on the path

The best path is the one with the minimum total cost from source to destination. The cost metric can be hops, distance, delay, capacity, reliability, or a mix of these.

8.2

Distance vector (Bellman–Ford)

Dx(y) = minv { c(x, v) + Dv(y) }
Dx(y)
least cost from router x to destination y
c(x, v)
cost of the link from x to its neighbour v
Dv(y)
neighbour v's advertised cost to y

In round one a router knows only its direct neighbours, and every other entry is ∞ (unreachable). It updates whenever a neighbour's vector changes or a link goes up or down.

Example
B's neighbours: A (cost 2), C (cost 1) A says A→E = 5, C says C→E = 3 D_B(E) = min(2 + 5, 1 + 3) = 4 via C
8.3

Distance vector vs link state

Distance vectorLink state
Sends toNeighbours onlyAll routers in the area (flooding)
Sends whatEstimated cost to every destinationExact cost of its own links
WhenPeriodically, every 30 sWhen a link changes
Failure reactionSlowFast
AlgorithmBellman–FordDijkstra
ExamplesRIP, EIGRPOSPF

Inside one AS (interior): RIP, OSPF, EIGRP. Between ASs (exterior): BGP.

Forwarding

8.4

Matching a destination

Destination AND row mask = row network address ?
  1. Go through the rows from the longest mask to the shortest.
  2. The first row where the AND gives that row's network address wins: forward to its next hop through its interface.
  3. No match: use the default route 0.0.0.0/0, which matches everything.
  4. No default route: send a "host unreachable" error back to the sender.
8.5

Slide example: router R1

Destination 180.70.65.130
/26: 130 AND 192 = 128 → 180.70.65.128 → no match /25: 130 AND 128 = 128 → 180.70.65.128 → match → interface m0
Destination 25.8.2.10
/26 → 25.8.2.0, /25 → 25.8.2.0, /24 → 25.8.2.0, /22 → 25.8.0.0 None match → default route → next hop 180.70.65.200, interface m2
8.6

Making tables smaller

  • Network-specific: one row per destination network, not per host.
  • Host-specific: one row for a single host address, checked first.
  • Default route 0.0.0.0/0: everything else.

Source and destination hosts need no forwarding table: they use their default router.

CHAPTER 09

Transport layer: UDP and TCP

Breakdown: transport

TCP numbers bytes, not segments, and almost every calculation question here depends on that one fact.

Sequence and acknowledgment numbers

9.1

Next sequence number

Seqnext = Seqprev + bytes carried by the previous segment
Range = Seq … Seq + bytes − 1

The first segment's sequence number is the initial sequence number (ISN), which is chosen at random when the connection is set up.

Example 9.8: 5000-byte file, first byte 10,001, 1000 bytes per segment
Seg 1 → 10,001 (10,001 – 11,000) Seg 2 → 11,001 (11,001 – 12,000) Seg 3 → 12,001 (12,001 – 13,000) Seg 4 → 13,001 (13,001 – 14,000) Seg 5 → 14,001 (14,001 – 15,000)
9.2

Acknowledgment number

ACK = last byte received + 1

ACKs are cumulative: ACK = X means every byte up to X − 1 arrived, and the receiver expects byte X next. If the timer runs out before the ACK arrives, the sender retransmits.

Slide data-transfer example
Client sends 8001–9000 and 9001–10000 Server: seq 15001, ACK 10001, carries 2000 bytes (15001–17000) Client: seq 10001, ACK 17001 (ACK only)
Watch out The ACK is the next byte expected, not the last byte received.
9.3

Number of segments

Segments = ⌈ file sizebytes per segment ⌉

5000 bytes ÷ 1000 bytes = 5 segments (example 9.8).

Windows, ports and headers

9.4

Send window = the other side's receive window

My send window = peer's advertised receive window
Slide example
Client receive window = 10,000 → server send window = 10,000 Server receive window = 5,000 → client send window = 5,000

Windows are announced during the three-way handshake (SYN, SYN+ACK, ACK) and can change at any time. Both sides have their own windows because TCP is full duplex.

9.5

Ports and sockets

Port: 16 bits → 0 … 65,535
Socket address = IP address + port number

Well-known ports 0–1023 are assigned by IANA and given to servers. A connection is identified by the pair of socket addresses (source IP, source port, destination IP, destination port), so two clients can both use source port 49888 to reach port 80.

9.6

Header sizes

TCP header = 20 … 60 bytes
UDP header = 8 bytes

TCP is 20 bytes by default and up to 60 with options. UDP's checksum covers the whole segment and is optional.

10.1

DNS at a glance

Port 53 (UDP or TCP)

DNS normally uses UDP because a request and its response each fit in one datagram.

10.2

Reading a domain name

FQDN = labels from the node up to the root, separated by dots

The root's label is the empty dot. Only an FQDN can be resolved to an IP address. A PQDN (partial name) is completed by the resolver, which adds the local suffix.

Slide name
lab.CS.PSU.EDU.SA. host → department → university → edu → sa → root
10.3

Zone transfer

The primary server loads its zone from a disk file. The secondary server loads everything from the primary; this copy is called a zone transfer.

Caching saves the result of a lookup so the next query for a name outside the server's domain is answered faster.

Recursive vs iterative

RecursiveIterative
Who asks the next serverEach server asks the next one itselfThe local server asks every server in turn
