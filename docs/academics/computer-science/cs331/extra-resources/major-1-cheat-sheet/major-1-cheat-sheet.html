A

Scenario questions

The instructor's own example: "definition, justification, advantage, disadvantage, like star topology". Answer in that order, every time:

  2. Define it. One sentence from the slides.
  3. Justify it. Point at the words in the scenario that led you there ("the office wants one central device…").
  4. Advantages that matter for this scenario.
  5. Disadvantages — at least one, honestly stated, plus how to live with it.
B

Computation questions

  1. Write the formula first, in words.
  2. Convert units before substituting: km → m, bytes → bits (× 8), ms → s.
  3. Substitute and show the arithmetic on one line.
  4. Give the answer with a unit, then convert to the unit asked for (Kbps, ms, μs).
  5. For parity, CRC and checksum: show the sender side and the receiver check, and state "accept" or "reject".

CHAPTER 01 · PART 1

Data communications, networks and topologies

Breakdown Tutorial 1 solutions

Expect a topology scenario and a "draw it / count the links" question from this part.

Definitions

1

Data communication

The exchange of information between two devices through a transmission medium.

5 parts
Message, sender, receiver, transmission medium, protocol
Message
Text (Unicode bit patterns), numbers (binary), images (bit patterns), audio, video (images in rapid succession)
2

Network

A set of devices (nodes) connected by communication links.

Node
A host (computer, printer, phone) or a networking device (router, switch, modem)
Link
The pathway that carries data between devices; wired or wireless
Point-to-point
A dedicated link between exactly two devices
Multipoint
One link shared by more than two devices
3

Data flow (transmission mode)

ModeMeaningExample
SimplexOne direction onlyKeyboard, monitor, TV, radio station
Half duplexBoth directions, one at a timeWalkie-talkie
Full duplexBoth directions at once; capacity shared by bothTelephone
4

Network criteria

Performance
Measured by throughput and delay (transit and response time). Depends on number of users, medium, hardware and software. Throughput and delay contradict: more throughput means more data in the network, which raises delay.
Reliability
Frequency of failure and time to recover from a failure.
Security
Protecting data from unauthorized users and damage; policies to recover from breaches and data loss.
5

Network types

LAN
A room, building or campus (e.g. two buildings)
MAN
A town or city (e.g. STC across a city)
WAN
Long-distance transmission: countries, continents
internet
Any networks joined by connecting devices (routers)
Internet
The global collection of networks running the TCP/IP suite

To be on the Internet a host must run TCP/IP, have an Internet (IP) address, and be able to send IP packets to other machines.

6

ISPs and peering

Tier 1
International backbones, few, connected directly to each other (Sprint, AT&T, Lumen)
Tier 2
National/regional providers, connected to at least one tier-1 (STC, ITC, Mobily)
Tier 3
Local ISPs, buy service from national providers
Private peering
Direct connection, owned and operated by the ISPs themselves
IXP
Public peering point run by a third party; any ISP can connect (Saudi Arabian Internet Exchange)

Trend: international ISPs meet at private peering points; national ISPs interconnect through IXPs.

7

Protocols and standards

Protocol: a set of rules controlling the exchange of data between two entities. Its elements are syntax (format), semantics (meaning) and timing.

Why standards: early vendors (IBM, Digital) built networks only their own machines could join. Standards give interoperability between vendors, a large market for equipment and software, and guidelines for manufacturers, vendors and governments.

Organizations: ISO, ITU-T (UN agency), ANSI, IEEE (LAN/MAN standards), W3C.

8

Peer-to-peer vs client/server

Peer-to-peer
  • Each machine is client and server
  • No central server, no single point of failure
  • Cheap; suits a few machines sharing work
  • Hard to administer at scale
Client/server
  • Central server provides services
  • Central management, backups, security
  • Server is a single point of failure and a cost
  • Scales to large organisations

Topologies: draw, count, defend

Topology = the way a network is physically built: how devices interconnect across the network. N = number of devices.

T1

Mesh

Definition
Every node has a dedicated point-to-point link to every other node.
Links
N(N − 1)/2 — N = 5 gives 10
Ports
N − 1 NICs / I/O ports per device; cables = links
Advantages
  • Dedicated links: secure, no traffic problems (no congestion)
  • Robust: one failed link doesn't stop the network
  • Easy to find faulty links
Disadvantages
  • Hard to install and update (too much wiring)
  • Expensive: many cables and N − 1 ports per device
Choose it whenfew sites, reliability and security matter more than cost (bank branches, research cluster, WAN backbone).
T2

Star

Definition
Each node has a dedicated point-to-point link to a central controller (hub/switch) only. Nodes are not linked to each other.
Links
N; each device needs one port
Advantages
  • Less expensive than mesh
  • Easy to install
  • Easy to add and remove devices
  • Robust: one broken cable affects one device
  • Easy to find faulty links
  • Secure, but less than mesh
Disadvantages
  • If the central device fails, the whole network stops (single point of failure)
  • More cable than bus or ring
Choose it whenan office wants central management and easy growth. This is the usual LAN today.
T3

Bus

Definition
One long backbone cable; each node taps in with a drop line. Terminators close both ends.
Links
1 main cable + N drop lines (multipoint)
Advantages
  • Easy to install
  • Less cabling than mesh and star
Disadvantages
  • Hard to isolate a fault
  • Hard to add new devices
  • A break in the bus stops all transmission
Choose it whena small, cheap, temporary network; mention the break weakness.
T4

Ring

Definition
Each node has a dedicated point-to-point link with the two nodes on either side of it; the signal passes around the ring.
Links
N
Advantages
  • Easy to install
  • Less cable
  • Easy to add or remove a device
  • Easy fault isolation
Disadvantages
  • Not robust: one broken link or node can stop the ring
T5

Hybrid

A combination of topologies, e.g. a star backbone with three bus networks, star–bus, or star–ring. Use it when departments already have their own networks and need to be joined centrally.

CHAPTER 01 · PART 2

Protocol layering, OSI and TCP/IP

Breakdown

Understanding questions: what each layer does, its PDU, its address, and why layering is worth it.

1

Why layers?

Network architecture is too complex to handle as one piece, so functions are grouped into layers. Layer n − 1 provides a service to layer n through a well-defined interface.

Advantages
  • Breaks a complicated process into simpler ones: easier hardware/software
  • Each layer is implemented independently, so different manufacturers can supply different layers (collaboration and competition)
  • One layer's implementation can be replaced without affecting the others
Note
  • Not every device uses all layers; complexity grows with the number of layers a device supports
2

Encapsulation and PDUs

PDU = data (payload) from the layer above + this layer's control information (header). The data link layer adds a header and a trailer.

Encapsulation: layer N − 1 carries the whole PDU of layer N in its data part without knowing its content. Each header is read only by the peer layer on the receiving node (peer-to-peer communication).

Ethernet | IP header | TCP header | DATA | trailer
 frame      packet      segment    message
3

OSI vs TCP/IP

OSI
7 layers, developed by ISO in the 1970s, a framework for standardization; dominated before 1990. An open system lets any two systems communicate regardless of architecture.
TCP/IP
5 layers, developed in the 1970s, named after TCP and IP. The lower four match OSI's lower four; OSI's session, presentation and application are one application layer.
Implementation
Application, presentation, session, transport: software. Network: hardware + software. Data link and physical: hardware in the NIC.
Mnemonic (top → bottom)All People Seem To Need Data Processing: Application, Presentation, Session, Transport, Network, Data link, Physical.

Signals

S1

Analog vs digital

Analog data
Continuous values (sound, light, temperature)
Digital data
Discrete values (text, integers)
Analog signal
Continuously varying wave, infinite values
Digital signal
Voltage pulses, limited values (1 = positive voltage, 0 = zero)
Periodic
Repeats over identical periods (cycles)
Aperiodic
No repeating pattern

Data communication commonly uses periodic analog and aperiodic digital signals. Data must become electromagnetic signals to be transmitted.

S2

Simple vs composite; frequency

Simple signal: one frequency (a sine wave). Composite: several sine waves with different frequencies, amplitudes or phases.

Frequency is the rate of change with time: change in a short time = high frequency; over a long time = low frequency. Most digital signals are aperiodic, so frequency doesn't apply to them; use bit rate and bit interval.

S3

Advantages of digital transmission

  • Low-cost technology
  • Longer distances using repeaters
  • Security and privacy (encryption)
  • Noise is easily removed
  • Cheaper, easier multiplexing (many sources on one link)
  • Computer can process both analog (voice, video) and digital data

Transmission media

M1

Twisted pair

Two insulated copper wires twisted in a spiral to reduce interference from nearby pairs (more twists = better quality). Used in the telephone subscriber loop and LANs. Connector: RJ-45.

  • Suffers from EMI
STP

Straight-through: PC–switch/hub, router–switch/hub. Crossover: same-type devices: PC–PC, hub–hub, switch–switch, hub–switch, router–PC.

M2

Fiber optic

Core (thin glass/plastic fiber) + cladding (different optical properties) + jacket (protects against moisture and crushing). Carries light pulses.

Advantages

  • Smaller, lighter
  • Lower attenuation: 50 km+ without repeaters
  • No crosstalk, not affected by noise
  • Highly secure (no light leaks)
Disadvantages
  • Needs special skills to install
  • Expensive interfaces

CHAPTER 03 · PART 1

Data link layer: framing, error detection and correction

Breakdown Tutorial 4

Tutorial 4 is all parity, CRC and checksum. Learn the procedures below until you can run them without thinking.

D1

Data link services

  • Framing / deframing: pack bits into frames with header and trailer
  • Addressing: physical (MAC) addresses in the frame header
  • Error control: detect and correct errors
  • Flow control: sender must not send faster than the receiver can process
  • Access control: who uses a shared link (part 2)
D2

Byte and bit stuffing

A flag (usually 01111110) marks the start and end of a frame. If it appears inside the data:

Byte stuffing
Character-oriented. Sender adds an ESC byte before every flag or ESC byte in the data; receiver removes the ESC and treats the next byte as data.
Bit stuffing
Bit-oriented. Sender adds a 0 after five consecutive 1s; receiver removes a 0 after five 1s; if the sixth bit is 1, it's the flag.
Example
Data: 0111111111100 Stuffed: 011111011111000
D3

Error types

Single-bit
Only 1 bit of the data unit changes
Burst
2 or more bits change; not necessarily consecutive. Length = first corrupted bit to last corrupted bit.
Bits affected = data rate × burst duration
Slide
2 ms burst: 1 Kbps → 2 bits; 1 Gbps → 2,000,000 bits

To detect or correct, we must send redundant bits: codeword C(n, k), n = k + r.

Detection procedures

P1

Simple parity (even)

  1. Count the 1s in the dataword.
  2. Parity bit = 0 if even, 1 if odd, so the total is even.
  3. Receiver counts the 1s in the codeword: even → accept, odd → reject.
Tutorial 4 Q2
1010101 → 10101010 1111000 → 11110000 0000000 → 00000000 Received 10101010 valid | 11110001 invalid | 00000001 invalid
Can't correctParity only says "odd number of bits flipped"; it can't tell which bit, so the receiver can only reject. It misses any even number of errors.
P2

Two-dimensional parity

  1. Write the datawords as rows.
  2. Add a parity bit at the end of each row.
  3. Add a parity row for each column, including the parity column (corner bit).
  4. Receiver rechecks every row and column. A failing row + failing column cross at a single bad bit, which can be corrected.
Tutorial 4 Q1 (sender)
1010 | 0
0111 | 1
1100 | 0
1001 | 0
-----+--
1000 | 1

Detects 1, 2 or 3 errors; not all 4-bit errors. Corrects a single-bit error.

P3

CRC

  1. Generator: write the polynomial as bits, e.g. x³ + x + 1 → 1011. r = generator length − 1.
  2. Append r zeros to the dataword.
  3. Divide with modulo-2 division: XOR, no borrows. When the leading bit is 0, XOR with 0000.
  4. The r-bit remainder is the CRC; codeword = data + CRC.
  5. Receiver divides the whole codeword by the same generator: remainder 0 → accept; otherwise reject.

Checksum (one's complement)

  1. Split the message into k-bit words (16 in the Internet).

Correction

C1

Retransmission vs FEC

Retransmission is inefficient when:

  • Wireless: the bit error rate is very high, so there would be a huge number of retransmissions.
  • Real-time multimedia: waiting for a resend creates unacceptable delay.

Forward error correction (FEC) detects and corrects a limited number of errors without retransmission:

  • Two-dimensional parity
  • XOR: send R = C₁ ⊕ C₂ ⊕ … ⊕ Cₙ with the codewords; a corrupted block = XOR of R with all the other blocks
  • Chunk interleaving for burst errors: mix chunks so a lost packet removes only one chunk from each packet, which multimedia can tolerate
C2

CHAPTER 03 · PART 2

Media access control

Breakdown

The problem: when two or more nodes on a shared (broadcast) link send at once, frames collide and bandwidth is wasted. MAC protocols coordinate who sends.

1

Two sublayers

LLC
Logical link control: error and flow control
MAC
Media access control: framing, MAC addressing, multiple access

Three families: random access (CSMA, CSMA/CD), controlled access (reservation, polling, token passing), channelization (FDMA, TDMA, CDMA).

2

Random access: CSMA

No station is superior; each decides by itself. Carrier sense: listen to the medium before sending. This reduces collisions but cannot eliminate them, because of propagation delay.

Vulnerable time = maximum propagation time

Max propagation time: time for a bit to travel between the two most widely separated stations. The longer it is, the worse CSMA performs.

3

CSMA/CD

CSMA wastes the channel while colliding frames finish. With collision detection the sender keeps listening while it transmits. On a collision:

  1. Abort the transmission.
  2. Send a 48-bit jam signal so every station discards the frame.
  3. Back off a random time.
  4. Rerun the persistence method.

Used by Ethernet (IEEE 802.3) on a bus, or a star with a hub.

4

Random access performance

Good
  • Simple, easy to implement
  • Decentralized: no central device to fail
  • Low delay in light traffic
  • A lone sender gets the full rate R
Bad
  • Unbounded delay in heavy traffic
  • Unfair: a station may never send
  • With M senders, throughput per node is less than R/M (collisions)
5

Controlled access

Ordered, fair access; no collisions; each node gets R/M.

Reservation
Each cycle starts with a reservation frame of N minislots (one per station). Stations that reserved send in order at full rate R.
Polling
Centralized: a primary station; select = primary wants to send to a secondary; poll = primary asks each secondary if it has data (data or NAK). Distributed: no primary; access passes down a known order (reservation and token passing are examples).
Token passing
A token circulates in a ring. A station waits for a free token, marks it busy with its data and destination; the destination takes the data and frees the token.
6

Channelization

FDMA
Bandwidth split into M frequency bands; each station sends continuously on its band at R/M, even when alone
TDMA
One channel shared in time; a station waits for its slot, R/M even when alone
CDMA
One channel carries everyone at once; each station encodes with its own code, receivers decode with it
7

Persistence methods

MethodIdleBusyResult
Non-persistentSendWait a random time, sense againFewer collisions; wasted idle time if backoff is long
1-persistentSend immediatelyKeep listening, send with probability 1 when idleNo idle time; "selfish", collision guaranteed if two wait
p-persistentSend with probability p, else wait one slot (1 − p)Keep listening, then repeatFewer collisions and less idle time. Slot = max propagation delay.

Local area networks: Ethernet

Breakdown

Ethernet: a LAN data link protocol for bus and star topologies that uses CSMA/CD. Original DIX Ethernet (Digital, Intel, Xerox) 1980; IEEE Project 802 started 1985.

MAC (802.3)

5

Full duplex

Traditional Ethernet is half duplex because of CSMA/CD. Full duplex sends and receives at once, so throughput doubles: 100 Mbps → 200 Mbps; 1 Gbps → 2 Gbps.

Requirements:

  1. Full-duplex NICs
  2. Two wire pairs: one host → switch, one switch → host
  3. A switch, not a hub, as the central device
  4. Point-to-point (dedicated) links to the switch

Each station is its own collision domain, so CSMA/CD is no longer needed.

Star topology. Each device has a dedicated point-to-point link to a central hub or switch only.

Justification: the clinic asks for one central device, easy expansion and easy troubleshooting, which are exactly star's properties.

Advantages: cheaper than mesh (15 links vs 105), easy to install, add or remove a PC with one cable, robust (one broken cable affects one PC), easy to find faulty links.

Disadvantage: if the central device fails the whole network stops; keep a spare switch.

Drawing: the star diagram in tab 1.1 — 5 links.

Scenario · Ch 1

A bank links its 4 main data centres and needs maximum reliability, privacy and no congestion. Which topology, how many links and ports, and why?

Show answer

Mesh. Every centre has a dedicated link to every other.

Links = 4 × 3 / 2 = 6; ports per centre = 4 − 1 = 3.

Justify: dedicated links mean no shared traffic (no congestion) and privacy; if one link fails, traffic goes through another centre (robust); faults are easy to locate.

Disadvantage: expensive and hard to install; acceptable for only 4 sites.

Scenario · Ch 1

A company has three departments, each already running its own bus network. They want to connect them through one central device. What topology results? Draw it.

Show answer

A hybrid topology: a star backbone with three bus networks. The central hub is the star; each department stays a bus. See the hybrid drawing in tab 1.1.

Advantage: reuses existing networks; a fault in one bus doesn't affect the other departments. Disadvantage: the central hub is a single point of failure for inter-department traffic, and each bus keeps its break weakness.

Scenario · Ch 1.2

A file sent from a mainframe (EBCDIC) shows garbage on a PC (ASCII). Which OSI layer should fix this, and what else does that layer do?

Show answer

Presentation layer, through translation: the sender converts to a common format and the receiver converts to its own. It also does encryption/decryption and compression.

Scenario · Ch 2

A factory LAN beside heavy motors has many errors. Name the impairment, its category, and two fixes. Which medium would you recommend and why?

Show answer

Induced noise (electromagnetic interference), a type of noise.

Fixes: shielded twisted pair, move cables away from the motors, error detection/correction.

Fiber optic: carries light, so it is completely immune to EMI, and it also gives long distance and security. Disadvantage: higher cost and installation skill.

Scenario · Ch 3

A live video stream over a noisy wireless link shows errors. Should the receiver ask for retransmission? Justify and propose a technique.

Show answer

No. The wireless bit error rate is high, so retransmissions would be huge, and real-time video can't wait for a resent frame.

Use forward error correction: XOR the codewords into a block R and send it, so one corrupted block can be rebuilt; or chunk interleaving, so a lost packet loses only one chunk of each frame, which viewers barely notice.

Scenario · Ch 3.2

A factory control network needs every station to get a guaranteed turn with no collisions. Which family of MAC protocols? Name and describe one.

Show answer

Controlled access: fair, collision-free, each node gets R/M.

e.g. Token passing: a token circulates; a station sends only when it holds the free token, marks it busy with its data, and the destination frees it. Or centralized polling with select/poll from a primary.

Scenario · Ch 4

An office upgrades from a hub to full-duplex 100 Mbps Ethernet. What must change, and what throughput can each station reach?

Show answer

Full-duplex NICs, two wire pairs per link, a switch instead of the hub, and dedicated point-to-point links to the switch. Each station is its own collision domain, so CSMA/CD is unnecessary. Throughput: 200 Mbps (2 × 100).

A 2-MB file is sent over a 4-Mbps link, 6,000 km long, at 2 × 10⁸ m/s. Find transmission time, propagation time, and which dominates.

Show answer
Transmission = 2 × 10⁶ × 8 / 4 × 10⁶ = 4 s
Propagation  = 6 × 10⁶ m / 2 × 10⁸ = 0.03 s = 30 ms
Transmission dominates (long message, modest bandwidth)

Tutorial 4, worked

Q1 · 2-D parity

Data 1010, 0111, 1100, 1001, even parity. (a) Build the block. (b) Check the received block with rows 1010|0, 0111|1, 1100|0, 1001|1 and parity row 1011|0.

Show answer
(a) 1010 | 0
    0111 | 1
    1100 | 0
    1001 | 0
    -----+--
    1000 | 1

(b) Row 4 (1001|1) has three 1s: fails. Columns 3 and 4 fail. The data rows are unchanged, but the row-4 parity bit and the parity row (1011|0 vs 1000|1) differ: errors are detected, so the block is rejected. More than one bit is wrong, so it can't be corrected.

Q3 · Checksum 16-bit

Words 1100110011001100 and 1010101010101010. (a) Checksum. (b) Receiver gets checksum 0110010101100101.

Show answer

(a) Sum with wrap = 0111011101110111 → checksum 1000100010001000. Packet: word1, word2, 1000100010001000.

(b) Sum of the three words = 1101110011011100 → complement 0010001100100011 ≠ 0 → error, reject. (The received checksum doesn't match the correct one.)

Q4 · Checksum

1111000011110000 + 0000111100001111 with checksum 0000000000000000. (b) What if the checksum arrives as all 1s?

Show answer

(a) Sum = 1111111111111111 → complement 0000… → no error.

(b) 1111111111111111 + 1111111111111111 = 1 1111111111111110 → wrap → 1111111111111111 → complement 0 → still accepted. One's complement has two zeros (0000… and 1111…), so this corruption is not detected: a weakness of checksum.

Q6 · CRC 1101

Codeword 10101010101, generator 1101. (a) Receiver gets 10101010111. (b) Receiver gets 10101010101.

Show answer

(a) Remainder 001 → error detected, reject.

(b) Remainder 011, not 0. The "transmitted" codeword in the question isn't a valid CRC codeword for 1101: the correct CRC for 10101010 is 110, giving 10101010110. Say this in the exam and show the division.

(a) Generator 1011, CRC 110 (division in tab 3.1) → frame 101110110.

(b) Remainder 011 → reject. (c) Remainder 010 → reject.

Q8 · 2-D parity

Data 111, 000, 101. (a) Block. (b) Received 111|1, 000|0, 101|0, parity row 010|0.

Show answer
(a) 111 | 1
    000 | 0
    101 | 0
    ----+--
    010 | 1

(b) All rows and data columns pass, but the parity column (1, 0, 0, 0) has an odd number of 1s: only the corner bit is wrong (0 instead of 1). The data itself is correct.

Q9 · 8-bit checksum

10101010, 01010101, 11110000, 00001111.

Show answer
10101010 + 01010101 = 11111111
11111111 + 11110000 = 1 11101111 → wrap → 11110000
11110000 + 00001111 = 11111111
Checksum = 00000000
Receiver: sum incl. checksum = 11111111 → complement 0 → accept
Q10 · All three on 1101

(a) Even parity. (b) CRC with 1011. (c) Checksum with 2-bit words 11 and 01.

Show answer

(a) Three 1s → parity 1 → 11011; receiver counts four 1s (even) → accept.

(b) 1101000 ÷ 1011 → CRC 001 → frame 1101001; receiver remainder 000 → accept.

(c) 11 + 01 = 100 → wrap → 01 → checksum 10; receiver 11 + 01 + 10 = 11 (after wrap) → complement 00 → accept.
