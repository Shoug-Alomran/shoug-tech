Slide 3 / 54

Protocol Layers and Service Models

Notes

  1. 1

    A network involves cables, signals, addresses, routes, error checks, applications and much more. If one program had to handle all of it, nobody could build it, understand it or fix it. The question on the slide is how developers and users can cope with that complexity.

  2. 2

    The solution is to split the work into layers. A layer is a logical grouping of related functions: one layer only worries about turning bits into signals, another only about finding a route, another only about getting a whole message to the right program. Each layer solves one part of the problem and trusts the others to do theirs, and the layers exist on every node in the network.

  3. 3

    Layers are stacked, and each one uses the services of the layer below and provides a service to the layer above: layer n-1 serves layer n. The meeting point between two neighbouring layers is called the interface. It defines exactly what information, operations and services the lower layer offers the upper one, like a menu. As long as the interface stays the same, a layer’s inside can be changed without affecting anyone else.

  4. 4

    Memory trick A layer only talks to the one directly above and below it on the same machine.

Slide 4 / 54

Layers, protocols, and interfaces

Notes

  1. 1

    Read the figure in two directions. Horizontally, layer 3 on host 1 follows the same rules as layer 3 on host 2: those rules are the layer-3 protocol, and the two layer-3s are called peers. Vertically, each layer hands data to the layer directly below it on the same host through an interface. So: protocol = between the same layer on different machines; interface = between adjacent layers on the same machine.

  2. 2

    The peers never actually send anything directly to each other. Layer 3 on host 1 passes its data down to layer 2, then to layer 1, and only layer 1 puts signals on the physical medium. On host 2 the data goes back up. The horizontal conversation is logical (it feels direct to the layer), while the real path is down, across and up.

  3. 3

    Trap Protocol ≠ interface. A protocol is between peers on different machines; an interface is between neighbours on the same machine.

Slide 5 / 54

Communication through an internet

Notes

  1. 1

    Not every device on the path needs every layer. The hosts (source A and destination B) use all five, because the data starts and ends in an application. A link-layer switch only uses layers 1 and 2: it reads the frame’s MAC address and forwards the frame on the same network. A router uses layers 1 to 3: it reads the IP address to decide which network to send the packet to next. Neither looks at the transport or application data.

  2. 2

    The more layers a device implements, the more work and processing it does, so the more complex it is. A host is the most complex, a router is in the middle, a switch is simpler, and a repeater or hub (layer 1 only) is the simplest. This ranking comes back in Chapter 6 on connecting devices.

Slide 6 / 54

Advantages of Layered Architecture

Notes

  1. 1

    The first advantage is simplicity: one huge, complicated process becomes several smaller, simpler ones, so the hardware and software for each layer are easier to implement and easier to test and fix.

  2. 2

    The second advantage comes from two rules: each layer has its own distinct set of protocols (no two layers do the same job), and there is a well-defined interface between neighbouring layers. Together these mean each layer can be built independently. A network card maker can build layers 1 and 2, an operating system maker layers 3 and 4, a browser maker layer 7, and the result still works because each respects the interfaces. That lets different manufacturers work on different layers, which encourages both collaboration and competition.

Standard Protocol Models

Notes

  1. 1

    The set of protocols used by all the layers together is called a protocol stack, because the protocols are stacked one above the other, like the layers.

  2. 2

    There are two standard stacks. OSI (Open Systems Interconnection) is the 7-layer reference model from ISO; it is mainly used to teach and discuss networking. TCP/IP is the suite the Internet actually runs. You need both: OSI for the vocabulary (people still say “layer 7” or “a layer-3 switch”), and TCP/IP for what really happens.

Slide 8 / 54

OSI Model

Notes

  1. 1

    OSI stands for Open Systems Interconnection. It was developed by ISO, the International Organization for Standardization, in the 1970s, as a framework for standardising networks. An open system is a set of protocols that lets any two systems communicate regardless of their underlying architecture: an IBM machine and a Mac can talk as long as both follow the model. The model describes how data moves from an application on one computer to an application on another. It dominated before 1990, after which TCP/IP took over in practice. Watch the letters: ISO is the organisation, OSI is the model.

  2. 2

    Trap ISO is the organization, OSI is the model. Exam options often swap them.

OSI Protocols Implementation

Notes

  1. 1

    A layer can be built in software, in hardware, or both. The upper layers deal with data and programs, so they are software; the bottom layers deal with signals and timing, so they need hardware. The split: application, presentation, session and transport are software (part of the operating system and the applications). The network layer is mixed hardware and software (routers have special forwarding hardware, and hosts run IP in software). The data link and physical layers are in hardware, on the network interface card (NIC): the card builds the frames, checks the MAC address and turns bits into signals.

Peer-to-Peer Processes

Notes

  1. 1

    Peers are the processes at the same layer on different machines; the communication between them is called peer-to-peer. In the figure, device A’s layer 4 is the peer of device B’s layer 4, even though their data actually travels down, across and up.

  2. 2

    Look at which layers the intermediate nodes have: only 1 to 3. That means layers 4 to 7 talk end to end: A’s transport layer talks directly to B’s, and the routers in between never touch it. Layers 1 to 3 talk hop by hop: A talks to the first router, which talks to the next, and so on. This end-to-end vs. hop-by-hop split is one of the most tested ideas in the deck.

Slide 13 / 54

OSI model-Basic Operation

Notes

  1. 1

    Each layer talks to its peer using formatted blocks of data called Protocol Data Units (PDUs). A PDU has two parts: the data (payload) handed down by the layer above, and the current layer’s own control information (requests and instructions for its peer). Every layer builds its own PDU, which is why each layer’s PDU has a different name (slide 51).

  2. 2

    The control information goes in a header in front of the data. The data link layer is the only exception: it adds a header and a trailer at the end. The trailer holds the error-detection code (such as a CRC), which is placed at the end so it can be calculated as the bits go out.

  3. 3

    A header is read and acted on only by the peer layer on the receiving node. The receiver’s transport layer reads the transport header; it never looks at the network header (the network layer already removed it). That rule is what keeps the layers independent.

  4. 4

    Trap Only the data link layer adds a trailer (for error detection).

Data Encapsulation

Notes

  1. 1

    Encapsulation means a layer puts the entire PDU from the layer above inside its own data field, without looking inside or changing it. The network layer doesn’t know or care that there is a TCP header in its data; to it, it is just bytes to carry. Think of putting a sealed letter inside an envelope, then that envelope inside a courier bag: each wrapper adds its own label but never opens what is inside.

  2. 2

    As a formula: PDU of layer N-1 = PDU of layer N + control information of layer N-1. For example, a packet (layer 3) = a segment (layer 4) + an IP header; a frame (layer 2) = a packet + an Ethernet header and trailer.

Notes

Slide 26 / 54

Physical Layer

Notes

  1. 1

    The physical layer deals with the actual medium. It defines the physical characteristics of the interfaces and the media: how devices connect to each other and to the link (topology), the shape, size and number of pins of connectors, which voltages and currents are used, what type of medium (twisted pair, fibre, wireless), and the transmission mode (simplex, half- or full-duplex).

  2. 2

    It also decides how bits are represented: each bit is encoded into an electrical or optical signal (for example, one voltage for 1 and another for 0). It sets the data rate, the number of bits sent per second, also called the transmission rate. And it handles synchronisation of bits: the sender and receiver clocks must agree, so the receiver samples each bit at the right moment and doesn’t miss or double-count bits.

  3. 3

    Devices that work only at this layer: the repeater (regenerates a weak signal) and the hub. The network card also has a physical-layer part (the part that sends and receives signals). They don’t read addresses at all, they only handle signals.

Slide 28 / 54

Data Link Layer

Notes

  1. 1

    The data link layer’s PDU is the frame. Its job is node-to-node (hop-to-hop) delivery: moving a frame across one direct link from one node to the next node. It doesn’t plan the whole route; it only gets the frame safely across the current link.

  2. 2

    Two duties are on the slide. Framing: dividing the stream of bits into frames, so the receiver knows where each unit starts and ends. Physical addressing: putting the sender’s and receiver’s physical addresses in the frame header. The physical address has many names that all mean the same thing: MAC address, hardware address, NIC address, LAN address, local address. It is burned into the network card.

  3. 3

    The MAC address says which device on the current link should receive the frame. In A ── Router ── B, A’s frame carries the router’s MAC as destination, because the router is the next device on A’s link. The router then builds a new frame with B’s MAC for the next link. So the MAC addresses change at every hop.

  4. 4

    Trap Destination MAC = the NEXT HOP, not the final host. Destination IP = the final host.

Slide 33 / 54

Network Layer

Notes

  1. 1

    The network layer’s PDU is the packet, also called a datagram. Its job is source-to-destination (host-to-host) delivery: getting a packet from the original sender all the way to the final destination host, possibly across many networks. This is the difference from the data link layer, which only crosses one link.

  2. 2

    To do that it needs logical addressing: a globally unique address that identifies each host on the Internet, called the IP address. Unlike the MAC address, which is burned into the card and only matters on the local link, the IP address says where the host is in the network as a whole.

  3. 3

    Routing: the connecting devices (routers) decide the best path for each packet towards its destination and forward it. Each router looks at the destination IP address and picks the next hop. That is the core of Chapters 7 and 8.

  4. 4

    Memory trick IP = end-to-end destination. MAC = next-hop destination.

Slide 38 / 54

Transport Layer

Notes

  1. 1

    The transport layer is responsible for process-to-process delivery of the entire message. A host runs many programs (processes) at once; the network layer gets data to the right computer, and the transport layer gets it to the right program on that computer.

  2. 2

    The network layer treats every packet independently: it doesn’t know that packet 1 and packet 2 belong to the same message, so they may take different routes and arrive out of order. The transport layer makes sure the whole message arrives intact and in order: it splits the message into pieces, numbers them, and puts them back together at the receiver.

  3. 3

    The transport layer’s PDU is the segment. Its address is the port address (port number), which identifies a process: for example, port 80 for a web server, 25 for email. So, bottom-up: MAC finds the device on the link, IP finds the host, and the port finds the process.

    Seen again Ch 9, slide 3: Transport-layer services

Slide 44 / 54

Session

Notes

  1. 1

    The session layer sets up, manages and ends sessions (connections) between applications, and keeps each application’s data separate from the others. Examples on the slide: an FTP program downloading several files at once, several Telnet (remote login) connections from one host, or browsing many web pages at the same time. Each is its own session.

  2. 2

    Dialog control: the session layer decides who may send when. The two processes can talk in full-duplex (both at once) or half-duplex (taking turns).

  3. 3

    Synchronisation: the session layer inserts checkpoints into a long transmission. If the connection crashes, the transfer can continue from the last checkpoint instead of starting over. For example, if a 1,000-page transfer has a checkpoint every 100 pages and fails at page 523, only pages 501 onward are resent.

TCP/IP Protocol Suite

Notes

  1. 1

    TCP/IP was developed in the 1970s. It is a suite (a family) of protocols named after its two most important ones, TCP (transport) and IP (network), but it includes others such as UDP.
