CH 1–2

Fundamentals and authentication

Security goals and attacks

  • CIA + authentication, non-repudiation, access control.
  • Passive attacks (eavesdropping, traffic analysis: hard to detect, prevent with encryption) vs active (masquerade, replay, modification, DoS: detect and recover).
  • Defense in depth; security services vs mechanisms (X.800).

Identification, authentication, authorization

  • Factors: something you know, have, are (+ somewhere you are).
  • MFA combines different factors.
  • Protocols: password, challenge-response, Kerberos (tickets, KDC = AS + TGS), RADIUS/TACACS+, 802.1X (EAP).
  • Authorization models: DAC, MAC, RBAC, ABAC.
CH 3, 6

DES, AES, RC4 and modes

DES and 3DES

  • 64-bit block, 56-bit key (+8 parity), 16 Feistel rounds, S-boxes give non-linearity.
  • 3DES: EDE with 2 or 3 keys (112/168-bit). Broken DES by brute force (56 bits too short).

AES

  • 128-bit block; 128/192/256-bit keys → 10/12/14 rounds.
  • Round: SubBytes → ShiftRows → MixColumns → AddRoundKey (last round has no MixColumns).
  • Not a Feistel network (substitution-permutation network).

RC4 (stream)

KSA initializes a 256-byte state from the key; PRGA produces the keystream XORed with plaintext. Weak first bytes and related-key flaws broke WEP; now deprecated.

Modes of operation

  • ECB: blocks encrypted separately (patterns leak).
  • CBC: XOR with the previous ciphertext; needs an IV; sequential.
  • CFB / OFB: stream-like; OFB keystream independent of the plaintext.
  • CTR: encrypt a counter; parallel, random access.
  • GCM: CTR + authentication (AEAD).
CH 4, 5, 8

RSA, ECC and Diffie-Hellman

RSA

n = p q, phi = (p-1)(q-1), gcd(e, phi) = 1, d = e^-1 mod phi
encrypt C = M^e mod n     decrypt M = C^d mod n
p = 5, q = 11: n = 55, phi = 40, e = 3, d = 27 (3 x 27 = 81 = 2 x 40 + 1)
M = 7 -> C = 343 mod 55 = 13

Security rests on factoring n. Signatures use the private key.

Diffie-Hellman

public p, g; A = g^a mod p, B = g^b mod p
K = B^a mod p = A^b mod p
p = 23, g = 5, a = 6, b = 15
A = 5^6 mod 23 = 8      B = 5^15 mod 23 = 19
K = 19^6 mod 23 = 2  =  8^15 mod 23 = 2
Plain DH has no authentication: vulnerable to man-in-the-middle. Fix with signed or certificate-based DH.

Elliptic curve cryptography

Curve y² = x³ + ax + b (mod p); security from the elliptic-curve discrete log problem. Same security with much smaller keys (256-bit ECC ≈ 3072-bit RSA), so faster and lighter (ECDH, ECDSA).

CH 7, 9

Hash functions and key management

Hash properties

  • One-way (preimage resistance), second-preimage resistance, collision resistance; fixed-length output; avalanche effect.
  • MD5 128-bit (broken), SHA-1 160-bit (broken), SHA-256/512, SHA-3.
  • HMAC = hash with a secret key (integrity + authentication). Birthday attack: collisions after about 2^(n/2) tries.

Key distribution

  • Symmetric: a KDC shares a master key with each user and issues session keys (Kerberos, Needham-Schroeder).
  • Public keys: certificates signed by a CA (X.509), PKI, CRL/OCSP for revocation.
  • n users with pairwise symmetric keys need n(n−1)/2 keys.
CH 10, 13

Protocols and VPNs

IPsec

  • AH: integrity and origin authentication, no encryption. ESP: encryption (+ optional authentication).
  • Transport mode: protects the payload (host to host). Tunnel mode: wraps the whole packet (gateway to gateway, VPNs).
  • IKE negotiates SAs and keys (Diffie-Hellman).

TLS / SSH

  • TLS handshake: hello and cipher suite → server certificate → key exchange (ECDHE) → finished; then symmetric encryption + MAC. HTTPS = HTTP over TLS (443).
  • SSH (22): secure remote login, tunnels, SFTP.
  • Others: S/MIME and PGP (email), DNSSEC (signed DNS), SNMPv3.

VPNs

  • Site-to-site (gateway ↔ gateway) vs remote access (client ↔ gateway).
  • Technologies: IPsec, SSL/TLS VPN, (legacy PPTP, L2TP/IPsec).
  • Split tunneling: only corporate traffic goes through the tunnel (convenient, riskier).
CH 11–16

Firewalls, IDS/IPS, honeypots, SIEM and data security

Firewalls

  • Packet filter (stateless: IPs, ports, protocol), stateful inspection (tracks connections), application proxy / gateway, NGFW (app awareness, IPS), WAF (HTTP).
  • Rules are read top-down, first match wins, end with deny all.
  • DMZ between two firewalls holds public servers. Segmentation and VLANs limit lateral movement.

IDS / IPS

  • IDS detects and alerts (out of band); IPS blocks inline.
  • NIDS vs HIDS. Signature-based (known attacks, low false positives) vs anomaly-based (unknown attacks, more false positives).
  • False positive = alarm without attack; false negative = missed attack (worse).
  • Snort, Suricata.

Honeypots and proxies

  • Honeypot: decoy system to attract and study attackers; low vs high interaction; honeynet.
  • Proxy: forward proxy (clients' requests out, filtering, caching) vs reverse proxy (in front of servers, load balancing, hiding servers).

SIEM and UBA

  • SIEM: collects and correlates logs from many sources, real-time alerts, dashboards, forensics, compliance reports.
  • UBA/UEBA: baselines normal user behaviour and flags anomalies (insider threats, compromised accounts).

Data security

  • Data at rest (disk/database encryption), in transit (TLS, VPN), in use.
  • DLP stops sensitive data leaving; classification, tokenization, masking, backups, secure deletion.
