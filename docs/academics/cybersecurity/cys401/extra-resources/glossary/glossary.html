Ch 1

Introduction to Cybersecurity

18 terms
A
Asset
Anything of value to an organization that needs protection, including data, systems, people, facilities, and reputation.
Attack
An intentional action that attempts to compromise the confidentiality, integrity, or availability of an asset.
Attack surface
The total set of points where an attacker could try to enter, extract data, or affect a system.
Availability
The property that authorized users can access information and services when they need them.
C
Cybercrime
Illegal activity in which computers, networks, or digital information are the target, tool, or place of the crime.
Cybersecurity
The people, processes, and technologies used to protect systems and information from unauthorized access, disruption, alteration, or destruction.
Cybersecurity framework
A structured set of cybersecurity functions, outcomes, and practices used to assess and improve an organization's security program.
D
Data
Recorded facts, observations, or measurements that can be processed into information.
Defense in depth
A strategy that layers people, processes, and technical safeguards so one failed control does not expose the whole system.
I
Information
Data organized and interpreted so it has meaning and can support decisions.
Information security
Protection of information and information systems against unauthorized access, use, disclosure, disruption, modification, or destruction.
Integrity
The property that information and systems remain accurate, complete, and changed only in authorized ways.
R
Risk
The possibility that a threat will exploit a vulnerability and cause harm to an asset, commonly considered in terms of likelihood and impact.
S
Security control
A safeguard or countermeasure that reduces risk by preventing, detecting, or responding to unwanted events.
Security program
The coordinated governance, policies, people, and controls an organization uses to manage information security.
T
Threat
A potential cause of an unwanted incident that could harm a system or organization.
Threat actor
A person, group, or organization that may carry out a threat, intentionally or unintentionally.
V
Vulnerability
A weakness in an asset, system, or control that a threat could exploit.
Ch 2

Security Foundations and Principles

20 terms
A
Accountability
The ability to trace actions to the person, process, or system responsible for them.
Accounting
Associating a user's actions with that user's identity so activity can be reviewed and attributed.
Authentication
Verifying that a claimed identity is genuine.
Authorization
Determining which actions or resources an authenticated identity is permitted to use.
C
CIA triad
The foundational security objectives of confidentiality, integrity, and availability.
Confidentiality
The property that information is disclosed only to authorized people, processes, or systems.
Countermeasure
An action, device, procedure, or technique that reduces a threat or vulnerability.
D
Denial of service (DoS)
An attack that makes a service or resource unavailable to legitimate users.
Distributed denial of service (DDoS)
A denial-of-service attack launched from many compromised or coordinated systems.
E
Exploit
Code, a command, or a technique that takes advantage of a vulnerability.
M
Malware
Software deliberately created to damage systems, disrupt operations, steal information, or provide unauthorized access.
P
Phishing
A social-engineering attempt that uses deceptive messages or sites to trick people into revealing information or taking an unsafe action.
R
Ransomware
Malware that blocks access to data or systems, commonly by encrypting files, and demands payment for restoration.
Repudiation
A denial by a user or system that an action or transaction occurred; logging and digital signatures can help address it.
S
Social engineering
Manipulating people into revealing information, granting access, or performing actions that weaken security.
Spyware
Software that secretly monitors activity or gathers information about a user or system.
T
Trojan horse
Malware disguised as a legitimate or useful program; it relies on a user to run or install it.
V
Virus
Malware that attaches itself to a host file or program and spreads when that host is executed or shared.
W
Worm
Self-propagating malware that spreads between systems, often across a network, without attaching to a host file.
Z
Zero-day vulnerability
A vulnerability for which the affected vendor or defenders have no available fix or have had no time to deploy one.
Ch 3

Threat Modeling

18 terms
A
Attack tree
A diagram that breaks an attacker's goal into the subgoals and steps that could achieve it.
Attack vector
The path or method an attacker uses to reach and exploit a target.
D
Data flow diagram (DFD)
A model showing processes, data stores, external entities, and the movement of data between them.
DREAD
A threat-ranking model that rates Damage, Reproducibility, Exploitability, Affected users, and Discoverability.
E
Elevation of privilege
An attack in which a user or process gains permissions beyond those intended.
Entry point
A location or interface through which data or a user can enter a system, such as an API, login page, or network port.
External entity
A person, system, or organization outside the system boundary that sends data to or receives data from the system.
I
Information disclosure
Exposure of information to a party that is not authorized to receive it.
M
Misuse case
A scenario that describes how an attacker or malicious user could misuse a system feature.
R
Risk analysis
The process of estimating likelihood and impact to prioritize risks and choose suitable responses.
S
Security requirement
A condition the system must meet to protect assets and maintain required security properties.
Spoofing
Impersonating a user, device, or service by falsifying identity information.
STRIDE
A threat-modeling mnemonic for Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, and Elevation of privilege.
T
Tampering
Unauthorized modification of data, code, configuration, or messages.
Threat model
A structured description of a system's assets, boundaries, attackers, threats, vulnerabilities, and mitigations.
Threat modeling
A repeatable process for identifying and prioritizing potential threats during system design and development.
Trust boundary
A point where data or control crosses between areas with different trust levels or security rules.
Trust level
The degree to which a component, user, or network is considered dependable for a particular security decision.
Ch 4

Protection of Information Assets

20 terms
A
Access control
Rules and mechanisms that decide who may access a resource and what actions they may perform.
D
Data at rest
Information stored on a device or medium rather than actively moving across a network.
Data classification
Assigning information to categories according to sensitivity, value, or required protection.
Data custodian
The role responsible for operating and maintaining information safeguards on behalf of the data owner.
Data in transit
Information moving between systems or locations over a communication channel.
Data in use
Information being accessed or processed by an application, user, or system.
Data minimization
Collecting and retaining only the information needed for a stated purpose.
Data owner
The person or role accountable for deciding how information is classified, used, and protected.
Data remanence
Residual information that remains on storage media after ordinary deletion or reformatting.
Data retention
Keeping information for a defined period to meet business, legal, or regulatory needs, then disposing of it appropriately.
I
Information asset
Information or a related resource that has value to an organization and requires protection.
M
Media sanitization
A process that makes access to data on storage media infeasible for a specified level of effort.
N
Need to know
A rule that grants access to sensitive information only when a person's duties require it.
P
Personally identifiable information (PII)
Information that can identify a person directly or when combined with other available information.
Privacy
Appropriate handling of information about people, including how it is collected, used, shared, retained, and disposed of.
Proprietary information
Nonpublic information owned or controlled by an organization, such as trade secrets or internal designs.
R
Record
Information preserved as evidence of an activity, decision, transaction, or obligation.
S
Secure disposal
Destroying or sanitizing information and media so that protected data cannot be recovered beyond the required standard.
Sensitivity
The degree of harm or loss that could result if information were disclosed, altered, or unavailable.
Storage media
A physical or electronic medium that stores data, including disks, flash memory, tapes, and mobile devices.
Ch 5

Cryptography

21 terms
A
Advanced Encryption Standard (AES)
A widely used symmetric block cipher with 128-bit blocks and 128-, 192-, or 256-bit keys.
B
Block cipher
A symmetric cipher that transforms fixed-size blocks of plaintext into ciphertext using a key.
C
Cipher
An algorithm used to encrypt and decrypt information.
Ciphertext
The encrypted, unintelligible output produced from plaintext by encryption.
Cryptanalysis
The study of analyzing or breaking cryptographic systems to recover information or keys without authorization.
Cryptography
The use of mathematical methods to protect information, including confidentiality, integrity, authentication, and nonrepudiation.
D
Data Encryption Standard (DES)
An older symmetric block cipher with an effective 56-bit key; it is no longer considered secure against brute-force search.
Decryption
Transforming ciphertext back into readable plaintext using the appropriate key and algorithm.
E
Encryption
Transforming plaintext into ciphertext so that it is unreadable without the appropriate decryption key.
H
Hash function
A one-way function that maps input data of arbitrary length to a fixed-length digest.
I
Initialization vector (IV)
A nonsecret value used with some encryption modes to ensure that repeated plaintexts do not produce predictable identical ciphertexts.
K
Key
A value used by a cryptographic algorithm to control encryption, decryption, signing, or verification.
Keyspace
The set of all possible keys that can be used by a cryptographic algorithm.
M
Message authentication code (MAC)
A keyed value used to check that a message came from someone holding the secret key and was not altered.
O
One-time pad
A cipher that is theoretically unbreakable when its key is truly random, as long as the message, used once, and kept secret.
P
Plaintext
Readable, unencrypted information that is input to encryption or recovered by decryption.
S
Salt
A unique random value added to a password before hashing to make identical passwords produce different stored hashes.
Stream cipher
A symmetric cipher that encrypts data one bit or byte at a time using a generated keystream.
Substitution cipher
A cipher that replaces each plaintext symbol with another symbol according to a rule or key.
T
Transposition cipher
A cipher that rearranges the positions of plaintext symbols without replacing the symbols themselves.
Triple DES (3DES)
A legacy symmetric cipher that applies DES three times; it is being retired because of performance and security limitations.
Ch 6

Asymmetric Cryptography and PKI

19 terms
A
Asymmetric cryptography
Cryptography that uses a mathematically related public key and private key for operations such as encryption, key exchange, or signatures.
C
Certificate authority (CA)
A trusted entity that verifies identities and issues digital certificates binding identities to public keys.
Certificate revocation list (CRL)
A signed list published by a certificate authority identifying certificates that were revoked before expiration.
Certificate signing request (CSR)
A request containing a public key and identity details that an applicant submits to a certificate authority.
D
Diffie–Hellman key exchange
A method that lets two parties establish a shared secret over an exposed channel; it does not by itself authenticate the parties.
Digital certificate
An electronically signed statement that binds an identity to a public key and may include validity and issuer information.
Digital signature
A cryptographic value created with a private key and verified with the matching public key to support integrity, origin authentication, and nonrepudiation.
E
Elliptic-curve cryptography (ECC)
Public-key cryptography based on elliptic-curve mathematics, offering strong security with comparatively small keys.
F
Forward secrecy
A property where compromise of a long-term key does not reveal previously established session keys.
M
Man-in-the-middle attack
An attacker secretly intercepts and may alter communication between two parties who believe they are communicating directly.
O
Online Certificate Status Protocol (OCSP)
A protocol for checking the current revocation status of a digital certificate.
P
Private key
The secret member of a public-key pair, held only by its owner and used for operations such as signing or decryption.
Public key
The shareable member of a public-key pair, used by others for operations such as signature verification or encryption.
Public key infrastructure (PKI)
The policies, roles, processes, and technologies used to issue, manage, validate, and revoke public-key certificates.
R
RSA
A public-key cryptosystem based on the practical difficulty of factoring the product of large prime numbers.
S
Secure Sockets Layer (SSL)
A predecessor to TLS for securing network communications; SSL versions are obsolete and should not be used.
T
Transport Layer Security (TLS)
A protocol that protects network communications using authenticated key exchange and symmetric encryption; it succeeded SSL.
Trust chain
A sequence of certificate signatures linking a website or user certificate to a trusted root certificate authority.
X
X.509
A widely used standard format for public-key certificates and certificate revocation lists.
Ch 7

Security Design Models and Capabilities

20 terms
A
Access control list (ACL)
A list attached to an object that specifies which subjects or groups may perform which actions on it.
Attribute-based access control (ABAC)
An access-control model that makes decisions using attributes of the subject, object, action, and environment.
B
Bell–LaPadula model
A confidentiality model commonly summarized by 'no read up, no write down' across security levels.
Biba model
An integrity model commonly summarized by 'no read down, no write up' to prevent lower-integrity information from contaminating higher-integrity data.
Brewer–Nash model
The Chinese Wall model, which limits access to prevent conflicts of interest between competing organizations.
C
Capability
A protected token or reference that gives a subject specific authority over an object.
Clark–Wilson model
An integrity model that uses well-formed transactions, separation of duties, and auditing to protect business data.
Complete mediation
The design principle that every access to every protected object should be checked for authorization.
D
Discretionary access control (DAC)
An access-control model where an object's owner can grant or revoke access to other subjects.
F
Fail-safe defaults
A design principle where access is denied unless it is explicitly permitted.
L
Least common mechanism
A design principle that minimizes shared mechanisms and resources among users to reduce unintended information flow.
Least privilege
Giving each user or process only the minimum permissions needed to perform its authorized task.
M
Mandatory access control (MAC)
An access-control model where a central policy enforces access according to security labels and clearances.
O
Open design
The principle that system security should not depend on keeping the design secret; protection should rely on well-managed keys and controls.
R
Reference monitor
A tamper-resistant mechanism that mediates access, is always invoked, and is small enough to be analyzed and tested.
Role-based access control (RBAC)
An access-control model that assigns permissions to roles and users to roles according to job responsibilities.
S
Security domain
A set of resources and operations governed by a common security policy.
Security lattice
A partially ordered set of security labels used to define permitted information flows between levels.
Separation of duties
Dividing a sensitive task among multiple people or roles so one person cannot complete it alone without oversight.
T
Trusted computing base (TCB)
The hardware, software, and controls responsible for enforcing a system's security policy.
Ch 8

Security Vulnerabilities, Threats and Countermeasures

19 terms
B
Buffer overflow
A flaw where a program writes more data into a buffer than it can hold, potentially corrupting memory or enabling code execution.
C
Common Vulnerabilities and Exposures (CVE)
A public identification system that gives known cybersecurity vulnerabilities standardized names and identifiers.
Common Vulnerability Scoring System (CVSS)
A framework for expressing the severity of a vulnerability using standardized metrics.
Cross-site request forgery (CSRF)
An attack that tricks a user's browser into sending an unwanted request to a site where the user is already authenticated.
Cross-site scripting (XSS)
An injection flaw that lets attacker-controlled script run in another user's browser in the context of a trusted site.
H
Hardening
Reducing a system's attack surface by disabling unnecessary services, changing insecure defaults, and applying protective settings.
I
Input validation
Checking that supplied data is the expected type, format, length, and range before processing it.
Intrusion detection system (IDS)
A system that monitors activity for signs of attacks or policy violations and raises alerts.
Intrusion prevention system (IPS)
A system that monitors activity and can automatically block or limit suspected malicious traffic.
P
Patch management
The process of assessing, testing, prioritizing, and deploying software updates that fix vulnerabilities or defects.
Penetration test
An authorized, time-bounded assessment that safely attempts realistic attacks to find and demonstrate security weaknesses.
Privilege escalation
An attack that gains higher permissions than the attacker or compromised process originally had.
S
Secure configuration
A system setup that follows approved security settings and removes unsafe defaults or unnecessary features.
Secure software development life cycle (SSDLC)
Integrating security requirements, threat analysis, secure coding, testing, and response throughout software development.
Security misconfiguration
An insecure setting, default credential, exposed service, or missing safeguard that leaves a system vulnerable.
SQL injection
An attack that changes a database query by inserting untrusted input into SQL code.
V
Vulnerability assessment
A process that identifies, classifies, and prioritizes security weaknesses, often using automated scanning.
Vulnerability management
The continuing cycle of discovering, assessing, prioritizing, remediating, and verifying vulnerabilities.
W
Web application firewall (WAF)
A control that filters and monitors HTTP traffic to help protect web applications from common attacks.
Ch 9

ICS and SCADA System Security

19 terms
A
Air gap
A physical or logical separation intended to prevent direct network communication between systems.
D
Distributed control system (DCS)
An industrial control system that uses distributed controllers to manage processes within a facility.
DNP3
Distributed Network Protocol 3, used mainly for communication between control equipment in utilities and other infrastructure.
H
Human–machine interface (HMI)
The interface operators use to monitor and control industrial equipment or processes.
I
Industrial control system (ICS)
A collection of control systems and related equipment used to operate industrial processes.
J
Jump server
A tightly controlled intermediary system used by administrators to access systems in a more restricted network zone.
M
Modbus
An industrial communications protocol used to exchange data between control devices; traditional deployments provide little built-in security.
O
Operational availability
The ability of an industrial system to perform its required function when needed, including during maintenance and recovery.
Operational technology (OT)
Hardware and software that monitors or controls physical devices, processes, and infrastructure.
OT network segmentation
Separating industrial networks into controlled zones and conduits to limit lateral movement and contain incidents.
P
Process historian
A system that records time-series data from industrial processes for monitoring, analysis, and troubleshooting.
Programmable logic controller (PLC)
A ruggedized industrial computer that reads inputs and executes control logic to operate machinery or processes.
Purdue model
A reference architecture that organizes industrial control environments into levels from physical processes and control devices to enterprise systems.
R
Real-time constraint
A requirement that a system respond within a defined time window; late responses may be unsafe or operationally incorrect.
Remote terminal unit (RTU)
A field device that gathers sensor data and can control equipment while communicating with a supervisory system.
S
Safety
Protection of people, equipment, and the environment from hazardous conditions; it is a primary concern in industrial systems.
Safety instrumented system (SIS)
A system of sensors, logic solvers, and final control elements that moves a process to a safe state when dangerous conditions occur.
SCADA
Supervisory Control and Data Acquisition: systems used to monitor and control geographically distributed industrial equipment.
Supervisory system
A control layer that gathers field data and lets operators issue commands to remote equipment.
Ch 10

Authentication and Access Control

20 terms
A
Account lockout
A control that temporarily blocks authentication after repeated failed attempts, reducing some password-guessing attacks.
Authentication factor
A category of proof used to verify identity: something you know, have, or are.
B
Biometric authentication
Identity verification using physical or behavioral characteristics such as fingerprints or facial features.
C
Credential
Information or an object presented to prove identity, such as a password, token, certificate, or biometric sample.
F
Federated identity
An arrangement where one trusted identity provider authenticates a user for multiple separate services.
K
Kerberos
A network authentication protocol that uses a trusted ticket-granting service and time-limited tickets.
L
LDAP
Lightweight Directory Access Protocol, used to access and manage directory information such as users and groups.
M
Multi-factor authentication (MFA)
Authentication that requires evidence from at least two different factor categories.
O
OAuth 2.0
An authorization framework that lets an application obtain limited access to a resource on a user's behalf.
Object
A resource, such as a file, database, application, or device, that a subject may request to access.
OpenID Connect (OIDC)
An identity layer built on OAuth 2.0 that enables clients to verify a user and receive basic identity claims.
P
Password hashing
Applying a one-way, deliberately costly password-hashing function with a unique salt before storing a password verifier.
Privileged access management (PAM)
Policies and tools for controlling, monitoring, and auditing high-impact administrative accounts and sessions.
R
Role-based access control (RBAC)
A model that grants permissions through roles assigned to users, simplifying access administration by job function.
S
SAML
Security Assertion Markup Language, a standard for exchanging authentication and authorization assertions between identity providers and services.
Security token
A physical or digital object used as proof of identity or authorization, often time-limited or cryptographically protected.
Single sign-on (SSO)
A mechanism that lets a user authenticate once and access multiple related services without signing in separately to each.
Subject
An active entity, such as a user or process, that requests access to an object.
T
Time-based one-time password (TOTP)
A short-lived authentication code generated from a shared secret and the current time.
Z
Zero trust
A security approach that continuously evaluates identity, device, context, and policy for each access request instead of relying on network location alone.
